Windows용 ‘게시 전 개인정보 노출 자가진단 도구’를 이어서 담당해주세요.

먼저 상세 인수인계 문서와 프로젝트 README.md, docs/verification.md를 읽고 실제 코드와 대조해주세요. 과거 계획서와 연구 문서는 당시 제안이므로 최신 사용자 결정과 현재 구현을 우선해주세요.

현재 확정한 방향은 Windows PC, React + TypeScript + Vite, 제목·본문 검사, 전체 원문의 위험도별 글자색, 오른쪽 위험도별 건수·후보 목록, 사용자 지정 위치의 수동 저장·불러오기입니다. 게시 전 직접 한 번 더 확인하라는 안내를 유지합니다. 작업 재개는 글 작성 → 저장 → 컴퓨터 종료 → 프로그램 실행 → 불러오기 → 이어서 작성입니다. 자동 저장이나 강제 종료 복구까지 승인된 것은 아닙니다.

실제 구현은 Python + FastAPI + ko-pii 1.16.0과 pywebview/WebView2를 사용합니다. 현재 규칙 기반 detect_all만 연결됐으며 별도 학습 모델은 없습니다. 원문을 외부 서비스로 보내지 않고 127.0.0.1에서 검사하는 구조를 유지해주세요.

세 합성 게시글의 기준은 research/community_cases_v1.json이고, 작업 파일과 결과는 output/community-review에 있습니다. 기대 항목 16개, 완전 9개, 부분 2개, 오분류 1개, 미탐 4개, 추가 오탐 10개입니다. 현재 후보 수는 C01 7, C02 9, C03 6입니다. 이 수치를 일반 정확도로 표현하지 마세요. 개선 전후에 원문 구간과 유형, 오탐·미탐을 함께 비교하고 정답을 출력에 맞춰 바꾸지 마세요.

관련 논문 6편과 규칙 보완·한국어 NER 비교 제안은 research/논문기반_오탐과_미탐_개선방안.md에 있습니다. 모델 연결은 이미 학습된 모델을 사용하게 하는 기능이고, 추가 학습은 별도 작업입니다. 모델 연결·학습, 자동 마스킹, 첨부/OCR, 검토 상태 저장, OneDrive 정책, 스마트폰·macOS, EXE 배포는 아직 구현·확정되지 않았습니다. 제가 다음으로 요청하는 범위를 확인해 작업해주세요.

UI는 깔끔하고 사용자가 읽기 쉬운 구성을 선호합니다. 후보를 찾아 검토하는 경험을 자동 수정보다 우선합니다. 이미 정한 플랫폼과 저장 방식을 다시 질문하지 말고, 남은 선택에 대해서는 실제 비교 가능한 근거를 준비해주세요.

작업 시작 시 인수 문서에서 이해한 현재 상태와 다음 요청에 관련된 남은 사항을 간단히 정리해주세요. 실행 확인에는 합성 자료와 별도 시험 창을 사용하고, 열려 있는 사용자의 미저장 글을 덮어쓰거나 종료하지 마세요. Git에는 인수 당시 커밋이 없으므로 제공된 소스 사본과 manifest를 먼저 보존해주세요.
