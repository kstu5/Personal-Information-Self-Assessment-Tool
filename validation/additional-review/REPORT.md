# 문서 검사 추가 점검

2026년 10월 25일. HWPX tail·OOXML 부가 정보·Word 사본 검증 수정본에 추가 합성 문서 2개를 넣어 실제 atonlee/koelectra-ko-pii-ner 모델과 인증된 로컬 API로 점검했다. 이번 점검은 증거만 추가했으며 제품 코드를 수정하지 않았다.

## 새로 재현한 문제

| 문제 | 재현 결과 | 권고 |
|---|---|---|
| 원본 파일명의 개인정보 유지 | `김민수_010-0000-1234_안내.docx`의 본문 개인정보는 가려졌고 재검사는 0건이었지만, 다운로드 파일명과 Content-Disposition에는 이름·전화번호가 그대로 남았다. | 원본 파일명도 검사 대상으로 삼고 개인정보 없는 기본 사본 이름을 제안한다. 사용자가 고른 최종 이름도 확인한다. |
| Word 단순 필드의 링크 주소 누락 | 화면 글자는 `문의하기`이고 `w:fldSimple/@w:instr`에 `HYPERLINK "mailto:sample@example.invalid"`가 들어 있는 문서에서 후보가 0건이었다. 내보내기를 허용했고 사본 재검사도 0건이었지만 XML 속성에는 이메일이 남았다. | 필드 코드에 저장된 값과 링크 주소도 위치를 구분해 검사한다. 명령 구문을 손상시키지 않도록 수정하거나 사용자가 링크·필드를 제거할 수 있게 한다. 지원하지 못하는 유형의 범위도 알린다. |

파일명 노출은 `backend/file_review.py`가 원본 이름의 stem을 그대로 사본 이름으로 쓰기 때문에 생긴다. 필드 코드 누락은 현재 추출기가 `instrText` 요소는 읽지만 `fldSimple`의 `instr` 속성은 읽지 않기 때문이다. 앞서 추가한 툴팁·도형 대체 텍스트·문서 변수 값과 다른 저장 방식이다.

## 이전 점검에서 남은 문제

- Excel의 서로 다른 이름 시트 두 개를 모두 같은 전체 가림 문자열로 바꾸면 이름 충돌로 저장이 실패한다. 고유한 대체 이름을 사전에 계획해야 한다.
- Word 현재 본문과 삭제 기록을 합쳐 `김민수이전`처럼 이름 후보 범위가 넓어지는 사례가 남아 있다. 문서의 변경 기록 구간을 별도로 추출해야 한다.

수정 우선순위는 추가 필드 코드 누락, 파일명 노출 방지, 변경 기록 경계, Excel 시트 이름 충돌 순서를 권한다. 이는 이번에 확인한 사례의 우선순위이며 전체 문서 유형을 검사했다는 의미가 아니다.

## 근거와 범위

- 로컬 전용 `results.json`: 초기 후보·읽은 본문, 사본 이름, HTTP 다운로드 파일명, 재검사 건수, 독립 XML 잔존 확인을 보관했다. 이 파일과 아래 재현 산출물은 GitHub에 포함하지 않으며 `validation/check_additional_cases.py`로 다시 생성할 수 있다.
- `simple_hyperlink.docx`, `simple_hyperlink__reviewed.docx`: 가상 이메일이 필드 코드에 들어 있는 원본과 실제 제공된 사본.
- `김민수_010-0000-1234_안내.docx`, `김민수_010-0000-1234_안내__reviewed.docx`: 파일명 노출 시험 원본과 다운로드 바이트를 보관한 사본. 로컬에 보관한 증거 파일 이름과 앱이 권장한 다운로드 이름은 구분한다.
- 두 원본은 시험 전후 해시가 같았다. 실제 개인정보나 외부 서비스 전송은 사용하지 않았다.

앞선 21개 문서의 지정 확인 지점 89곳이 통과한 결과와 별개인 추가 사례다. 새 사례가 발견됐으므로 해당 89/89 결과를 전체 문서의 누락 없음으로 확대해서 해석해서는 안 된다. MS Office에서의 화면·클릭 시험은 수행하지 않았다.
