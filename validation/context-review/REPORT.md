# 공유 문서 문맥 개선 전후 점검

2026년 10월 25일. 기준 제품 코드 `d04a74a`와 문맥 개선 작업본을 비교했다. 실제 atonlee/koelectra-ko-pii-ner·ko-pii와 인증된 파일 검사·내보내기 API를 사용했다. 모델 가중치나 외부 패키지는 바꾸지 않았다. 수정 작업본의 소스 해시와 입력 해시는 [요약](summary.json)에 기록했다.

## 예시 7개 전후 비교

[독립 확인 목록](../../examples/documents/검사_확인목록.md)의 이름·연락처·주소·생년월일·나이 등장 위치를 대조했다. Word 메모·작성자, Excel 숨김 시트도 포함한다. PDF는 글자층만 집계해 OCR 중복이 점수를 늘리지 않게 했다.

| 파일 | 기본 확인 지점 | 수정 전 완전 검출 | 수정 후 완전 검출 |
|---|---:|---:|---:|
| 배송 요청서 Word | 18 | 18 | 18 |
| 이력서 Word | 12 | 11 | 12 |
| 이력서 PDF | 12 | 11 | 12 |
| 당첨자 Excel | 32 | 31 | 32 |
| 행사 참가자 안내 Word | 20 | 20 | 20 |
| 행사 참가자 안내 PDF | 20 | 19 | 20 |
| 회의록 Word | 14 | 14 | 14 |
| 합계 | 128 | 124 | 128 |

이 표본의 완전 검출 비율은 96.9%에서 100%가 됐다. 이는 정해 둔 기본 확인 지점의 결과다. 파일 7개 중 PDF 2개는 Word와 같은 내용을 담고 있으므로 서로 다른 문서 내용 7개를 평가한 것은 아니다. 모든 개인정보 유형의 정확도나 완전한 개인정보 제거를 보장하는 수치가 아니다.

## 재현한 문제와 적용한 수정

1. **상세 주소의 끝 누락:** 이력서 두 형식과 당첨자 숨김 시트에서 마지막 호가 빠졌다. 모델이 이미 잡은 주소 뒤의 동·호·층을 제한된 범위에서 보완한다. 다른 후보나 줄바꿈을 넘어 확장하지 않는다.
2. **장소 주소의 조각 검출:** 행사 PDF의 장소 주소를 시와 로 12 같은 조각으로 잡았다. 주소·장소 등의 명시적 표제와 도로명·건물번호·상세 주소 형식이 있고 모델이 주소 조각을 이미 찾은 경우에만 하나로 묶는다. 표제 자체는 가리지 않는다.
3. **작성일·서명일을 생년월일로 오탐:** 이력서 두 형식에서 작성일을 생년월일로 잡았다. 현재 줄 또는 바로 앞의 짧은 필드 표제와 서명 문구를 본다. 실제 생년월일 표제·년생 표시는 보존하고, 명확하지 않은 날짜를 일괄 삭제하지 않는다. 예전 작성일 문구가 뒤의 다른 필드로 전파되지 않게 제한했다.
4. **업무용 명칭을 사람 이름으로 오탐:** Excel 시트의 공유용_명단 중 공유용을 이름으로 잡았다. 용도 표현 뒤에 명단·자료 등이 오는 구조를 구분한다. 단독 공유나 다른 실제 이름을 일괄 제외하지 않는다.
5. **Word 줄바꿈·탭 소실로 직책 누락:** 추천인 문장의 팀장과 다음 줄 전화가 팀장전화로 붙었다. Word의 강제 줄바꿈과 탭을 읽기·수정·저장 검증에서 보존해 직책도 검출한다. 직접 수정으로 구분자를 없애는 경우도 유효한 Word 텍스트로 변환하며 뒤 영역의 위치가 밀리지 않게 했다.
6. **영문 단어 일부와 기술 용어를 이름으로 오탐:** PDF 사본 재검사에서 Python의 일부인 th를 이름으로 잡았다. 영단어 중간의 불완전한 이름 후보를 구분하고, 별도 사례에서 발견한 업무 역량 Python도 같은 줄의 명확한 기술 문맥에 한해서 제외한다. 짧은 독립 영문 이름과 성명으로 명시된 값은 보존한다.

수정 전 원본의 확인된 오탐은 작성일 2곳과 공유용 1곳이었다. 수정 후 세 곳 모두 사라졌다. 전공과 직책의 추가 검출은 기본 정답 외의 문맥 정보이므로 오탐으로 세지 않았다. PDF 사본의 th 재검사 오탐도 재현되지 않았다.

## 사본과 부작용 확인

- 예시 7개 모두 실제 전체 가림 사본을 생성했다. XML·관계 파일·문서 속성·PDF 글자층을 앱 재검사와 별도로 읽어 알려진 정답 문자열의 잔존이 없음을 확인했다. 원본 7개의 해시는 유지됐다.
- 공개해야 할 작성일·행사일·발송일·회의 기한을 독립 추출로 확인했다. 당첨자 Excel의 발표일 10개 셀도 원본과 같고 내부 배송정보 시트의 숨김 상태도 유지됐다.
- Python 회귀 시험 85개를 통과했다. 날짜 문맥 전파 방지, 실제 생년월일·짧은 영문 이름 보존, 주소와 전화/식별번호 충돌 방지, Word 줄바꿈·탭 변경과 저장 검증을 포함한다.
- 다른 이름·날짜·주소를 사용하는 실제 모델 사례 10개를 모두 통과했다. 일정 날짜 오탐 4건과 기술 문맥 이름 오탐 1건을 줄이면서 각 사례의 필수 검출을 유지했다. 이 사례들도 합성 예시이며 외부 검증 데이터셋은 아니다.
- 기존 8개 형식 21개 문서도 다시 검사해 확인 지점 89/89를 유지했다. 제공된 전체 가림 사본 18개에는 알려진 원문 잔존이 없고, 미지원 문서 2개는 계속 차단됐다. 시트 이름 충돌로 실패하는 기존 사례 1개는 그대로 남았다.
- 기존 word_linebreak 예시의 이름과 전화는 줄바꿈을 포함한 정확한 원문 범위로 검출·가림됐다. 이 사례는 비교할 때만 줄바꿈을 접고 원문 위치로 다시 대응한다. 일부 글자만 덮는 후보를 완전 검출로 인정하지 않으며, 다른 사례의 비교 기준은 변경하지 않았다.

## 범위와 남은 사항

공통 검출 단계에 적용되므로 파일 검사와 게시글 검사에 함께 영향을 준다. 문서 추출 변경은 Word 줄바꿈·탭에 한정했다. UI·모델 가중치·지원 파일 범위는 바꾸지 않았다.

모델이 주소 후보를 전혀 찾지 못한 경우, 도로명 형식 밖의 주소, 학교·회사 등 모든 문맥 정보, 이미지 OCR의 일반 성능은 이 결과로 보장하지 않는다. 후보 재검사 0건만으로 개인정보 제거를 판정해서도 안 된다. 이번에는 사본을 원래 Office·한컴 프로그램에서 화면으로 다시 확인하지 않았으므로 전체 서식 호환성을 주장하지 않는다.

기존의 Excel 시트 이름 충돌, 현재 본문과 삭제 기록 경계의 이름 과검출, Word 단순 필드 코드 주소 누락, 사본 파일명의 개인정보 유지는 별도 후속 과제다. 관련 기록은 [추가 점검](../additional-review/REPORT.md)을 참고한다.
