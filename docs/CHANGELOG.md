# 변경·검증 이력

날짜별 적용 내역과 그 시점의 검증 상태를 기록합니다. 현재 기능과 사용법은 [README](../README.md)를 참조하세요.

## 2026-10-25 파일 검사 위험도 시각화

- 위험도별 카드 바로 아래에 검출 목록을 배치하고 높은 위험도부터 묶어 표시합니다. 검색·필터·선택·가림 방법과 변경 예정 내용을 함께 확인할 수 있습니다.
- 원문 위치 이동과 처리 미설정 표시를 보완했습니다. 필터 밖 선택과 일부 선택 상태도 표시합니다.
- PDF·이미지는 페이지 미리보기를 기본으로 열고, 실제 사본 확인 버튼은 미리보기로 이동합니다. Word 계열 문서의 텍스트 미리보기에는 원래 페이지 배치를 보여주지 않는다는 안내를 추가했습니다.
- TypeScript 검사·화면 빌드와 기존 가림 시험 5개 통과. 실제 모델로 검사한 가상 DOCX·XLSX·PDF에서 목록 조작, 숨김 시트, PDF 가림 사본 미리보기와 좁은 화면 배치를 확인했습니다. [화면 검증 기록](verification/file-review-ui-2026-10-25.md)에 범위를 남겼습니다.

## 2026-10-25 문서 추출과 수정 사본 검증 보완

- HWPX XML tail에 있던 변경 기록의 개인정보를 읽고 수정하도록 보완했습니다.
- Word·PowerPoint의 지원 도형 이름·대체 텍스트·제목, 링크 도움말, Word 문서 변수 값을 검토·수정 대상에 추가했습니다.
- Word의 수정 후 빈 서식 조각 때문에 저장이 거부되던 문제를 문단·필드 위치를 기준으로 검증하도록 고쳤습니다. 수정 값 불일치와 누락 필드는 계속 거부합니다.
- 회귀 시험을 포함한 Python 시험 54개 통과, 실제 A 모델·API의 문서 21개 재시험에서 지정 확인 지점 89곳 모두 후보에 포함됐으며 제공된 전체 가림 사본 18개에서 알려진 원문이 남지 않았습니다.
- Excel 시트 이름 충돌과 변경 기록 경계로 인한 이름 과검출은 후속 과제입니다. 상세 범위는 [파일 검사 적용 기록](features/file-inspection.md)을 참조하세요.

## 2026-10-25 저장소 정리

- 폴더를 용도별로 재분류했습니다: `reports/`, `scripts/{prepare,check,evaluate,build}`, `docs/{features,design,verification}`. 앱 코드는 바꾸지 않았습니다.
- Linux용 `scripts/setup.sh`, `scripts/start.sh`를 추가했습니다 (실험적).
- 문서의 개인 PC 경로를 `<root>`, `<desktop>` 같은 표기로 바꿨습니다.
- `.gitattributes`를 추가하고 테스트가 쓰는 `python-docx`를 `requirements.lock.txt`에 고정했습니다.
- README를 처음 보는 사람 기준으로 다시 구성하고 날짜별 이력은 이 문서로 옮겼습니다.

## 2026-10-24 파일 검사 기능 적용

시작 화면을 게시글 검사와 파일 검사로 나누고, 여러 파일을 열어 위치별로 가림·수정한 뒤 새 사본을 저장하도록 했습니다. A 모델과 기존 게시글 저장 기능은 유지했습니다. 지원 형식과 한도는 [파일 검사 적용 기록](features/file-inspection.md)에 있습니다. 실행 중인 구버전 창이 있다면 글을 저장하고 닫은 뒤 **게시전 실행.vbs**를 다시 실행해야 했습니다.

## 검증 상태

2026-10-21 가림 UI 적용 후 TypeScript 검사·화면 빌드, 마스킹 단위 시험 5개, 기존 실제 앱 화면 시험 12개 흐름, 새 가림 화면 시험 8개 흐름, Windows WebView2 시험을 통과했습니다. 선택 모드와 목록 직접 수정 보완 후 화면 시험 20개 흐름과 빌드를 다시 확인했습니다. 새 화면 시험은 반복 위치·5단계 위험도·긴 목록을 고정 후보로 검증하며, 기존 화면 시험은 실제 A 모델을 사용합니다. [가림 UI 적용 기록](features/masking-ui-integration.md)에 범위와 저장 동작을 정리했습니다.

2026-10-17 A 모델 적용 후 현재 PC에서 다음을 확인했습니다. 상세 구현과 결과는 [A 모델 적용 기록](features/model-a-integration.md)에 있습니다.

- Python 자동 시험 27개: 실제 탐지·문자 위치, 파일 기능·API 보호, 모델 파일 무결성, 모델 재사용·시간 초과 후 복구·중복 검사 거부·종료 중 정리.
- 이전 비교 시험의 120개 고정 사례: 앱 결과가 규칙 + A 모델의 이름·주소 역할 분담 결과와 모두 일치합니다. 모델 불러오기부터 추론까지 외부 연결을 차단했으며 연결 시도도 0회였습니다.
- 브라우저 통합 시험 12개 흐름: 실제 A 모델 결과·집계, 저장/다시 불러오기, Ctrl+S, 원제목 유지, 오류·취소·미저장 보호, 0건 안내, 지연 응답 무시, 320px/390px 표시, 외부 요청 없음.
- 실제 Windows WebView2 창: 앱 화면 로딩, 이름·상세 주소 검사, 저장·불러오기 연결, 창 닫기의 미저장 보호와 취소, 종료 후 서버·모델 프로세스 정리.

파일 선택 창의 경로 선택만 시험 코드에서 임시 경로로 대체했습니다. 디스크 읽기·쓰기는 실제로 수행했고 탐지 결과는 실제 엔진을 사용했습니다. OS 파일 선택 창에서 직접 폴더를 고르는 조작, PC 재부팅, 다른 LAN 기기에서의 접속, 다른 Windows PC에서의 설치는 별도 사용 확인이 필요합니다. 설치형 EXE 배포와 코드 서명은 아직 제공하지 않습니다.

이름·주소의 오탐·미탐은 여전히 존재합니다. 이전 비교 시험에서는 “박하차” 오탐과 띄어 쓴 이름 일부의 누락이 남았습니다. 예시 글의 “아래”, “두었던” 오탐과 주소 호수 누락은 이번 화면 시험에서 개선을 확인했습니다. 작은 시험 표본의 결과를 일반적인 탐지 정확도 보장으로 해석하지 않습니다. `docs/verification/verification.md`는 적용 이전 기록입니다.
