# 게시글 검사 / 파일 검사 분리 화면 설계

작성: 2026-10-22

상태: 사용자 요청에 따른 화면 시안과 기존 화면 영향 검토. 이 문서는 실제 앱 적용 완료 기록이 아니다. 앱 실행 코드, 탐지 모델, `.piipost` 저장 형식은 변경하지 않았다. 파일 검사 지원 형식·용량·OCR·파일 가림 및 내보내기는 아직 확정하지 않았다.

## 요청과 기본 구성

첫 실행 화면에서 왼쪽은 **게시글 검사**, 오른쪽은 **파일 검사**로 나눈다. 두 영역은 같은 크기와 강조 수준을 사용한다. 좁은 창에서는 게시글 → 파일 순서로 세로 배치한다.

- 게시글 검사: 제목·본문 작성 또는 붙여넣기 → 검사 → 기존 본문 중심 검토와 가림·수정 → 게시글 작업 파일 저장.
- 파일 검사: 검사할 문서 선택 → 파일 내용 읽기와 검사 → 파일명·발견 위치·개인정보 후보 확인.
- 두 기능은 독립적으로 시작한다. 파일 검사를 위해 게시글을 만들거나 제목을 입력할 필요가 없다.
- 앱 이름 `게시 전`은 유지하고 보조 문구를 `게시글과 파일, 공유 전 한 번 더`로 바꾼다.
- 상단에 `시작 / 게시글 검사 / 파일 검사`를 두어 현재 기능을 명확하게 표시한다.
- 첫 화면에서는 작업 단계 표시를 숨긴다. 각 기능으로 들어간 뒤 해당 기능의 단계를 보여 준다.

시안에는 시작 화면, 게시글 입력 화면, 게시글 예시 결과, 파일 선택 화면, 파일 예시 결과를 연결했다. 파일 선택은 가상 파일을 고르는 시연이며 실제 파일을 읽거나 검사하지 않는다. PDF는 위치 표시를 설명하는 예시이지 지원 확정이 아니다. 게시글 입력 내용은 기능 사이를 이동하는 동안 시안 메모리에 유지되며 외부로 전송하거나 위젯 상태에 저장하지 않는다.

## 파일 결과에서 먼저 구분할 정보

파일 검사 결과는 다음 세 가지를 함께 보여 주어야 한다.

1. **무엇을 검사했는지:** 파일명, 파일 형식, 읽은 페이지/시트 등 실제 검사 범위.
2. **무엇을 찾았는지:** 기존 5단계 위험도별 건수와 발견된 값·유형.
3. **어디에 있는지:** PDF라면 페이지, 스프레드시트라면 시트/셀, 텍스트라면 줄 등 해당 형식에서 실제로 확인 가능한 위치.

원본 파일을 그대로 표시하지 못할 경우 `추출한 내용`이라고 안내한다. 파일 전체 텍스트를 한 덩어리로 합쳐 게시글 결과처럼 보여 주면 원본에서 위치를 찾기 어려우므로 위치 정보를 유지해야 한다.

**검사 실패·일부만 검사·검사 완료 후 0건을 구분한다.** 암호가 걸린 문서, 지원하지 않는 형식, 읽을 수 없는 페이지, 스캔 이미지 등은 결과 0건으로 바꾸지 않는다. 이미지/OCR, 주석·메모·숨김 시트·문서 속성 등은 지원 여부를 먼저 정하고 실제 검사 범위를 표시한다.

파일 검사 결과의 `저장`이 원본 수정인지 검사 보고서 저장인지 모호해지지 않아야 한다. 초기 설계는 개인정보 후보와 위치 확인에 집중하며 파일 가림·수정본 저장 버튼은 넣지 않았다. 파일 가림은 형식 보존, 복사/검색으로 원문이 남는지 여부 등을 검증하는 별도 작업이다.

## 적용 순서 제안

1. 시작 화면과 상단 이동 구조, 게시글 전용 문구를 분리한다. 기존 게시글의 입력·검사·가림·저장 흐름이 그대로 작동하는지 확인한다.
2. 첫 지원 파일 형식을 정하고 파일 선택, 용량/읽기 오류, 내용 추출과 위치 연결을 구현한다. 지원하지 않는 형식은 명확히 안내한다.
3. 파일 결과 화면에 검사 범위와 위치별 후보를 연결한다. 실제 처리에 맞춰 진행 상태와 취소를 제공한다.
4. 필요하다면 여러 파일 검사, OCR, 검사 보고서 저장, 파일 가림을 각각 별도 범위로 확장한다.

파일 검사에서도 현재 atonlee/koelectra-ko-pii-ner 모델과 규칙을 재사용할 수 있지만, 문서 내용을 읽어 모델에 전달하고 검출 위치를 원본 파일 위치와 연결하는 기능이 추가로 필요하다. 게시글의 30,000자 제한을 파일 전체에 그대로 적용해 앞부분만 검사하는 방식으로 구현하지 않는다. 분할 처리와 검사 범위 표시는 실제 파일 형식과 처리 성능을 확인한 뒤 정한다.

## 시안 확인 범위

시안의 화면 이동, 기능 전환 후 입력 유지, 예시 작업 파일 불러오기, 예시 검사 파일 선택·취소, 파일 결과의 항목 선택과 위치 강조를 확인했다. 밝은/어두운 모드와 320px·736px·1024px 너비, 4개 주요 화면의 24개 조합에서 가로 넘침이 없고 실행 오류가 없음을 확인했다. 첫 화면과 파일 선택·결과, 작은 창의 어두운 모드는 이미지로도 확인했고 작은 창의 메뉴 줄바꿈을 보완했다. 확인 기록은 `tmp/post-file-design/inspection.json`에 있다. 실제 파일 검사나 모델 성능 시험은 이 디자인 작업에 포함하지 않았다.
