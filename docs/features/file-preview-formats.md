# 예시 파일 12종의 미리보기와 적용 방향

이 프로젝트는 이름·주소에 **atonlee/koelectra-ko-pii-ner**, 그 밖의 개인정보 유형에 **ko-pii 규칙**을 사용한다. 화면·검사 진행·결과·프로젝트 설명에 실제 모델을 명시했다. 기존 설치 경로의 `model-a`는 재설치와 경로 변경을 피하기 위해 유지하는 내부 이름이며 별도 모델을 뜻하지 않는다.

## 현재 적용한 보기

| 예시 파일 | 기본 미리보기 | 개인정보 확인·처리 |
|---|---|---|
| 01 교육일정 공유메일 `.txt` | 행 간격과 순서를 유지한 내용 화면 | 글자 선택 → 부분/전체 가림·직접 수정, 원본/적용 전환 |
| 02 추첨당첨자 발표명단 `.csv` | 행·열·빈 셀을 유지한 표 | 해당 셀에서 선택·수정, CSV 사본 생성 |
| 03 봉사자 현장배치표 `.tsv` | 탭으로 구분한 표 | CSV와 같은 흐름, TSV 사본 생성 |
| 04 외부교육 참가추천서 `.docx` | 변환한 문서 페이지 | 화면과 후보 목록 연결, 메모·속성은 전체 위치에서 별도 검토 |
| 05 행사운영 사전브리핑 `.pptx` | 슬라이드 페이지 | 슬라이드의 위치 선택, 발표자 노트·부가 정보 별도 검토 |
| 06 워크숍 참가협조공문 `.hwpx` | 읽어낸 본문으로 재구성한 내용 화면 | 원본/적용 비교·선택 수정·HWPX 사본. 메모·속성은 전체 위치에서 검토 |
| 07 시민교육 참가안내 `.hwp` | 추출 본문 내용 화면 | 위치 확인과 읽기만 가능. 수정 사본 저장 미지원 |
| 08 기념품 배송요청명단 `.xlsx` | 시트·셀 표, 숨김 영역 포함 | 셀별 선택·수정. 재계산 후 값 전용 사본 |
| 09 협력행사 회의록 `.pdf` | 실제 페이지 이미지 | 글자층·OCR 후보와 연결, 일부/전체 영역 가림 |
| 10 독서캠프 참가신청서 `.png` | 실제 이미지 | OCR 위치 선택·직접 영역 가림 |
| 11 기념품 수령확인서 `.jpg` | 실제 이미지 | PNG와 같은 흐름, 수정 사본은 PNG |
| 12 현장운영 연락명단 `.jpeg` | 실제 이미지 | PNG와 같은 흐름, 수정 사본은 PNG |

내용 화면·표 화면도 기존 원본/적용 미리보기 토글과 처리 지정 체크를 사용한다. 선택하지 않은 원문은 유지하며 실제 사본 생성·재검사는 별도다. 파일 목록은 동시에 8개까지이므로 12개를 시험할 때는 두 묶음으로 연다.

## 원래 문서 화면이 필요한 경우

**HWP·HWPX는 이번 내용 화면만으로 원래 페이지 배치를 확인할 수 없다.** 표의 테두리·병합, 글꼴, 쪽 나눔과 도형 배치를 그대로 재현하지 않는다. 내장 이미지는 별도 이미지 탭, 메모·기록·속성은 텍스트·위치에 남긴다. HWPX의 본문 순서는 section 번호와 문단 순서로 표시하고, 본문 밖 정보는 포함 개수를 알린다.

원래 배치가 필요하면 두 방향을 검토할 수 있다.

1. **PDF 사본으로 배치 확인:** 한글에서 PDF로 저장한 파일을 함께 검사한다. 한컴 공식 도움말의 [PDF로 저장하기](https://help.hancom.com/hoffice110/ko-KR/Hwp/file/to_pdf.htm)를 따른다. 앱에 새 변환 엔진을 추가하지 않고 PDF 페이지를 볼 수 있다. PDF의 가림은 PDF 사본에 적용되며 원래 HWP/HWPX를 고치는 기능은 아니다. 원래 파일의 메모·기록·속성 검토도 별도로 유지해야 한다.
2. **한글 변환 엔진 연결:** 원본과 수정 사본을 각각 PDF로 변환해 페이지를 표시하고, 문단과 화면 위치를 검증해 연결한다. 이 PC에는 한글 실행 파일이 있지만 자동화·배포 사용 조건·변환 중 대화상자·복잡한 문서의 배치·실패/취소 처리를 검증하지 않았다. [한컴 변환 API 안내](https://developer.hancom.com/en-us/docsconverter/guide/api/module)를 참고해 로컬 실행 조건과 비용을 별도 확인해야 한다. 이번에는 프로그램 자동 실행이나 새 엔진 설치를 하지 않았다.

XLSX는 전체 인쇄 페이지보다 셀 보기를 기본으로 두는 편이 숨김 영역을 함께 검토하기 좋다. 향후 인쇄 배치 화면을 추가해도 셀 보기와 병행한다. DOCX·PPTX는 기존 변환 페이지를 활용하되 메모·노트와 변환이 제한된 구조의 텍스트 보기 전환을 유지한다. PDF·이미지의 문구 교체는 지원하지 않으므로 현재는 영역 가림을 사용한다.

## 부담

이번 보완에는 새 실행 패키지나 외부 서비스를 추가하지 않았다. TXT·CSV·TSV·HWP·HWPX의 새 화면은 이미 추출한 본문·셀 정보를 사용한다. 표시를 바꾸기 위해 문서 전체를 이미지로 다시 변환하거나 모델을 다시 실행하지 않는다. 기존 Word·PPT의 변환 대기와 캐시는 유지한다. 한글 원본 배치를 위한 새 변환 엔진을 붙이면 설치 크기·변환 시간·메모리·배포 조건을 별도 측정해야 한다.

## 2026-10-25 검증

- 실제 모델과 인증 API로 예시 12/12의 기본 미리보기 데이터를 확인했다. DOCX는 1쪽, PPTX는 3쪽이다. TXT는 본문 12개, CSV는 셀 63개, TSV는 셀 56개, HWPX는 본문 18개·본문 밖 3개, HWP는 추출 본문 18개, XLSX는 셀 72개, PDF·이미지 4개는 각각 이미지 1개를 확인했다.
- TXT·CSV·TSV·HWPX에서 표시할 위치 하나를 부분 가림으로 선택해 사본 생성·재검사를 통과했다. CSV·TSV 사본의 표 크기와 읽기 정보가 유지됐다. 원본 12개 해시는 모두 유지됐다. 이 시험은 탐지 정확도 평가나 개인정보 전체 제거 시험이 아니다.
- 실제 화면에서 TXT 내용 보기, CSV의 셀 선택·부분 가림, HWPX의 본문 수정·메모 선택 시 전체 위치 이동, HWP의 읽기 전용과 저장 제한을 확인했다.
- 700px 창에서 내용 화면과 처리 패널이 세로로 배치되고 문서 너비 685px로 가로 넘침이 없음을 확인했다.
- Python 정규 시험 95개, 화면 관련 시험 11개와 TypeScript 검사·빌드를 통과했다. 추가 시험은 CSV/TSV의 빈 셀·빈 행·셀 내부 줄바꿈·수정 후 위치, TXT의 빈 행, HWPX의 본문/속성 구분, 형식별 기본 보기와 본문 정렬·구간 이동을 포함한다.
- 상세 API 응답·요약·스크린샷은 로컬 전용 `validation/qa/format-previews/`, 재현 도구는 [check_format_previews.py](../../validation/check_format_previews.py)에 있다.
