# 본문 중심 개인정보 검토·가림 적용 기록

적용일: 2026-10-21

같은 날 사용성 보완: 작은 다중 선택 체크박스를 **한 개씩 선택 / 여러 개 선택** 버튼으로 바꾸고 Ctrl 없이 연속 클릭하는 방법과 선택 개수를 표시했다. Ctrl+클릭도 보조 조작으로 지원한다. 목록 항목의 편집은 **직접 수정** 입력란을 즉시 열고 현재 가림 결과를 채운 뒤 포커스를 이동한다. 위쪽의 **작성 화면** 버튼은 **수정한 글로 이어쓰기**로 바꾸고 적용한 가림·수정을 가져간다는 안내를 추가했다. 전체 검토 취소나 정보별 추천 기능은 이번 보완에 추가하지 않았다.

사용자가 승인한 전체 본문 중심 시안과 후속 목록의 전환·취소 디자인을 실제 프로젝트에 적용했다. 이 변경은 개인정보 후보를 사용자가 처리하는 기능이다. A 모델, ko-pii 규칙, 후보의 위험도 판정 및 로컬 탐지 서버는 변경하지 않았다.

## 사용 흐름

1. 기존 작성 화면에서 제목·본문을 검사한다.
2. 위 대시보드에서 전체와 심각·높음·보통·낮음·참고 건수를 확인한다.
3. 전체 제목·본문의 색칠된 후보를 누르면 아래 편집 영역에 해당 위치를 표시한다. 마우스와 키보드 포커스로 위험도·유형을 확인한다.
4. 부분 가림, 전체 가림, 가리지 않음, 직접 수정 중에서 선택한다. 여러 항목/전체 선택은 부분·전체·가리지 않음을 함께 적용한다. 직접 수정은 한 항목에서만 사용한다.
5. 부분 가림 목록은 왼쪽, 전체 가림 목록은 오른쪽에 나타난다. 목록에서 전체로/부분으로 전환하거나 취소할 수 있다. 여러 개가 선택되어 있어도 목록의 버튼은 해당 항목 하나만 처리한다.
6. 목록은 6곳씩 표시한다. 전환한 항목이 보이도록 대상 목록의 페이지를 이동한다. 되돌리기는 최근 20개 변경의 처리 내용과 목록 페이지를 복구한다.

전체 가림은 고정 5칸 `█████`다. 부분 가림은 성명 첫 글자, 전화번호 앞 구간·마지막 4자리, 이메일 앞 글자·도메인 등을 남기고 나머지 일부를 `*`로 바꾼다. 주소는 첫 시·군·구까지의 지역 정보를 남기고 상세 부분을 가린다. 별도 유형 규칙이 없는 값은 첫 글자만 남긴다. 한 글자 후보는 `*`로 가린다. 직접 수정은 사용자가 원하는 별표 범위나 다른 표현을 입력할 수 있다.

취소는 처리 지정을 제거하고 원문으로 복원한다. 탐지 후보 및 위험도 표시는 그대로 유지한다. 가리지 않음은 사용자가 원문 유지를 지정한 것으로 별도 접기 목록에서 확인한다. 위험도 건수는 처리 전 탐지 기준이며 처리 후 안전성 점수가 아니다.

## 저장과 상태

- 본문은 원문/처리 결과를 전환할 수 있다. 보기 전환으로 저장 대상이 바뀌지는 않는다.
- 저장, 다른 이름으로 저장, Ctrl+S, 미저장 확인창의 저장하고 계속 모두 **처리 후 제목·본문**을 저장한다.
- 가림·수정이 저장할 글을 바꾸면 미저장 상태가 된다. 취소·되돌리기로 저장본과 같아지면 미저장 상태가 해제된다.
- 작성 화면으로 돌아갈 때 처리 결과를 작성 내용으로 가져온다. 실제 글이 달라졌다면 기존 검사 결과와 검토 기록을 초기화해 오래된 위치에 가림을 적용하지 않는다.
- `.piipost` JSON 버전 1 및 기존 파일 API를 유지했다. 원문·검출 위치·검토 선택·취소 기록은 파일에 추가 저장하지 않는다. 재실행하여 불러오면 처리된 글에서 다시 검사한다.
- 원문 파일을 보관하려면 다른 이름으로 저장한다. 검토 중 취소할 수 있는 원문은 메모리에만 보관하며, 원문 파일을 별도로 자동 생성하지 않는다.
- 직접 수정의 빈 내용 및 처리 후 글자 수 한도 초과를 막는다. 제목 300자/본문 30,000자 한도는 그대로다.

## 구현 위치

- `src/masking.ts`: 유형별 부분 가림, 전체 가림, 후보 위치 검증, 등장 위치별 글 조합.
- `src/PrivacyReview.tsx`, `src/review.css`: 대시보드, 전체 본문, 개별 편집, 적용 목록 및 되돌리기.
- `src/App.tsx`: 원문·처리 내용 연결, 저장 대상, 미저장 보호, 작성 화면으로 이어쓰기.

후보의 UTF-16 위치와 원문 일치, 중복 ID, 겹침, 위험도 및 필드를 검사한 후 편집 화면을 연다. 원문을 문자열 전체 치환하지 않고 검출된 위치로 조합하므로 같은 이름/연락처도 각각 다르게 처리한다. 사용자가 입력한 HTML 등은 React 텍스트로 출력하며 실행하지 않는다. 가림·보기 전환·취소에는 모델 재검사를 요청하지 않는다.

시험 파일은 `tmp` 아래 합성 자료만 사용했다. OS 파일 선택 창의 선택 경로는 시험 코드로 지정하고 실제 디스크 읽기·쓰기는 실행했다. 새 가림 화면 시험은 UI 동작을 안정적으로 비교하기 위해 고정 후보를 공급하며 모델 정확도 시험은 아니다. Windows 시험은 기존 네이티브 연결 점검이며 새 가림 기능의 모든 조작은 브라우저 시험에서 검증했다.

재현 명령:

```text
pnpm run check
pnpm run build
pnpm run test:masking
python run.py --headless --ready-file tmp/app-ready.json
node scripts/check/check_ui.cjs
node scripts/check/check_masking_ui.cjs
python scripts/check/check_desktop.py
```

UI 시험은 별도의 터미널에서 실행하며 `PLAYWRIGHT_MODULE`로 설치된 Playwright 위치를 지정할 수 있다. 시험 결과는 `tmp/ui-check/report.json`, `tmp/masking-ui/report.json`, `tmp/desktop-check/report.json`에 있다.
