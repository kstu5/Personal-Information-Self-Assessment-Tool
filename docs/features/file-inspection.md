# 파일 검사 적용 기록 · 2026-10-24

실제 React/FastAPI/Windows 앱에 파일 검사를 연결했다. 연구용 예제만 만든 상태가 아니다. 기존 A 모델(이름·주소)과 ko-pii 규칙의 역할, 게시글 `.piipost` 저장 형식은 유지한다.

## 2026-10-25 문서 누락과 Word 사본 검증 수정

- HWPX 글자 안의 변경 표시 뒤에 저장되는 XML tail도 원래 순서와 위치에 맞춰 검사·수정한다. 표시 자체와 주변 글자는 유지한다.
- Word 링크 도움말·문서 변수 값, Word/PowerPoint 도형 이름·대체 텍스트·제목, VML 대체 텍스트·제목, DrawingML 링크 도움말을 검사·수정한다. 내부 도형 ID·문서 변수 이름 등 구조를 연결하는 값은 이번 추가 대상이 아니다. 지원하지 않는 모든 부가 정보까지 처리한다는 의미는 아니다.
- Word에서 여러 서식 조각을 가로질러 가릴 때 빈 조각이 생겨도 문단 위치로 수정 결과를 검증한다. 비운 문단과 없어진 문단을 구분하고, 값 불일치·필드 누락 시 사본 제공을 거부한다. 외부 링크는 축소판 제거 후에도 관계 ID로 검증한다.
- 기존 시험과 추가 회귀 시험 총 54개를 통과했다. 실제 A 모델과 API로 가상 문서 21개를 재시험하여 지정한 개인정보 89곳이 모두 후보에 포함됐고, 제공된 전체 가림 사본 18개에서 알려진 원문 잔존은 없었다. Word 저장 실패 2건과 누락 사본 3건이 해결됐다. 지원 제한 2개는 차단을 유지했다.
- Excel 시트 이름 일괄 가림 충돌 1건과 현재 본문·삭제 기록이 합쳐져 이름 범위를 넓게 잡는 1건은 이번 수정 범위에 포함하지 않았다. 이미지 OCR 성능·Office/한컴 전체 호환성을 검증한 것은 아니다.

시험 원본·수정 전후 자료는 `test/`에 보관했다. 결과의 89/89는 작은 합성 표본의 지정된 확인 지점이며 일반적인 탐지 정확도 보장이 아니다.

## 사용 순서

1. 시작 화면에서 **파일 검사 → 파일 추가**를 선택한다. 최대 8개 파일을 추가하고 왼쪽 목록에서 자유롭게 전환한다. 각 파일의 선택·가림·확인 위치는 별도로 유지된다.
2. **검사한 영역과 지원 범위**를 읽는다. 지원하지 않는 구조는 후보 0건으로 통과시키지 않는다. 읽기 실패, 읽기만 가능, 사본 저장 가능을 구분한다.
3. 텍스트의 위험도 표시 또는 검출 목록에서 위치별 **부분 가림 / 전체 가림 / 가리지 않음 / 직접 수정**을 선택한다. 체크박스로 여러 항목을 선택할 수 있다. 아래 적용 목록에서도 방법을 전환·취소·편집한다.
4. 자동 검출이 놓친 텍스트는 **이 영역 직접 수정**으로 고친다. 이 수정이 같은 영역의 개별 가림 선택보다 우선한다. **이미지·페이지**에서는 가릴 부분을 드래그한다. 잘못 잡은 영역은 취소한 뒤 다시 지정한다.
5. **사본 생성·재검사**를 누른다. 새 파일로 저장하고 다시 읽어 검사한 결과와 실제 이미지 미리보기가 나온다. 남은 후보 목록도 제공한다. 결과와 제한을 확인한 뒤 **새 파일로 사본 저장**한다.

검사 위치를 보여주는 문서 텍스트 미리보기는 Word/한글/PowerPoint의 원래 편집 화면과 동일하지 않다. Excel은 시트 선택·셀 주소·숨김 셀을 포함한 표 보기를 별도로 제공한다. 원래 문서 서식은 가능한 범위에서 보존하며, 원래 편집 프로그램에서 최종 배치를 확인해야 한다.

앱 서버가 계속 실행 중이면 화면을 새로 열어도 열린 파일 목록·검사 결과·이미 생성한 사본을 다시 연결한다. 새로 열기 전의 저장하지 않은 가림 선택은 복원하지 않으며 안내를 표시한다. 앱을 완전히 종료한 뒤 작업을 복구하는 기능은 아니다.

## 현재 지원 범위

| 형식 | 실제 연결한 동작 | 주요 제한 |
|---|---|---|
| TXT | 행별 검사·직접 수정·UTF-8 사본 | UTF-8/UTF-16/CP949 읽기. 자동 인코딩 추정에 한계가 있다. |
| CSV·TSV | 셀별 검사·인용된 줄바꿈 유지·수정 사본 | CSV는 쉼표, TSV는 탭. UTF-8 BOM 저장. 수식으로 해석될 수 있는 셀 앞에 작은따옴표 추가. |
| DOCX | 문단·표·텍스트 상자·머리말·꼬리말·각주·일반 메모/작성자·저장된 변경 기록·문자형 속성 수정 | 내장 문서·차트·다이어그램·서명·매크로·임의 custom XML 등의 파일은 저장 제한. 변경 기록을 일괄 승인/거부하지 않음. |
| PPTX | 슬라이드·표·마스터 텍스트·발표자 노트·문자형 속성 수정 | 내장 문서·차트·다이어그램·미지원 댓글/미디어 등 저장 제한. 원래 PowerPoint에서 모든 기능을 검증한 것은 아님. |
| HWPX | 본문·표·읽을 수 있는 메모·작성자·추적 정보·속성 수정 | 지원하지 않는 BinData는 저장 제한. 기존 Preview 글자·이미지를 제거. 한글 프로그램 전체 기능 호환성 보장 아님. |
| HWP | hwplib로 추출 가능한 본문·표 검사 | **수정 저장 미지원**. 메모만 있는 파일은 읽을 수 있는 본문이 0개일 수 있으며 이를 별도 표시. HWPX 사본으로 변환 후 검토 권장. |
| XLSX | 지원 수식 강제 재계산 → 결과 확인 → 값 고정 → 셀·메모·작성자·숨김 영역·시트명·인쇄 머리말 검사/수정 → 재검사 | **값 전용 사본**. 외부 링크·정의된 이름·그림·차트·표 개체·피벗·조건부 서식·유효성 검사·필터·현대식 댓글·미지원 수식은 차단. 일반 메모용 VML만 허용. |
| PDF | 본문 글자층 + 전체 페이지 OCR, 선택 위치의 글자·픽셀 삭제 후 새 PDF로 저장, 실제 사본 페이지 미리보기 | 주석·양식·서명·첨부·링크·회전 페이지·실행 동작·숨김 레이어는 저장 제한. 목차·문서 속성·접근성 태그 등 부가 기능은 보존하지 않음. 경계와 겹친 주변 글자·도형도 지워질 수 있음. |
| PNG·JPG/JPEG | 한국어·영어 OCR, 검출 위치 또는 직접 지정 영역의 불투명 픽셀 가림, 새 PNG 저장 | OCR 오류를 사용자가 확인해야 함. 다중 프레임 미지원. JPEG 원본도 출력은 PNG. |
| 문서 내 PNG·JPEG·BMP | 이미지별 OCR·직접 영역 가림, 이미지 관계를 PNG로 교체 | SVG·WMF·EMF 등 다른 내장 형식은 저장 제한. 원본 이미지와 축소판을 출력에 남기지 않음. |

PDF·이미지의 **부분 가림은 별표 텍스트를 합성하지 않고 일부 글자 영역을 검게 지운다.** 일반 문서의 부분 가림은 `*`, 전체 가림은 `█████`다. 이미지에는 OCR 여백을 포함한 가림을 적용하므로 남길 글자가 조금 더 지워질 수 있다. 직접 드래그하여 원하는 범위를 지정할 수 있다.

미리보기·OCR·선택 영역 처리는 문서 전체의 개인정보를 완벽히 제거하는 보증이 아니다. 특히 OCR 이메일 오인식과 문맥에 따른 A 모델 결과 변화가 관찰됐다. **재검사 0건을 안전 보증으로 표시하지 않는다.** 문서 밖의 클라우드 버전 이력은 읽지 않는다.

## 원본·작업 사본·배포 사본

- 원본 바이트를 세션 전용 임시 폴더에 복사한다. 사용자 경로를 수정 API로 받지 않는다. 브라우저에는 추측하기 어려운 작업 ID만 전달한다.
- 전용 창에서는 실제 원본 경로와 SHA-256을 내부에서 보관한다. 사본 생성 전후와 저장 전 원본 변경을 확인한다. 브라우저 업로드는 선택 당시 바이트 사본만 알 수 있어 이후 원본 경로 변경을 감시하지 못한다.
- 출력은 별도 파일에 생성한다. 문자 편집은 같은 위치의 기대 문자열과 재추출 결과를 대조한다. 이미지 가림은 불투명 픽셀로 바꾸고 PNG로 기록한다. PDF는 redaction 적용 후 새 문서에 페이지를 복사하고 전체 저장한다.
- 실제 A 모델로 수정 사본을 다시 검사한다. 남은 후보가 있어도 사용자가 유지하기로 한 정보·오탐일 수 있으므로, 자동으로 없애지 않고 검토 후 저장하게 한다.
- 전용 창은 새 파일에만 저장한다. 검증된 바이트를 같은 폴더의 임시 파일에 완성한 뒤 기존 파일을 덮어쓰지 않는 방식으로 게시한다. 기존 경로·원본 경로·별칭·충돌 경로를 덮어쓰지 않는다. 저장 실패 시 중간 파일을 정리한다.
- 브라우저는 날짜·시각을 붙인 새 이름으로 다운로드한다. 실제 다운로드 위치와 이후 사용자가 파일을 이동/교체하는 동작은 브라우저/사용자 영역이다.
- 작업 제거·취소·앱 정상 종료 시 임시 사본을 정리한다. 강제 종료·정전 시 OS 임시 폴더의 `before-post-review-*`가 남을 수 있다. 복구·암호화 저장은 제공하지 않는다. 앱 종료가 아닌 브라우저 탭 종료만으로 개발 서버가 종료되지는 않는다.

## 처리 방식과 한도

- 여러 파일은 한 번에 하나씩 처리하여 CPU·메모리 경합을 줄인다. A 모델은 게시글과 동일한 지속 프로세스를 공유한다. 다른 검사가 사용 중이면 기다린다.
- 짧은 영역은 묶어 검사하되, 서로 다른 셀/문단 사이에 걸친 검출이 나오면 원래 영역별로 다시 검사한다. 경계에 걸친 결과를 임의로 잘라 적용하거나 버리지 않는다.
- 문서 파서는 별도 프로세스에서 실행한다. Python 문서 처리 프로세스는 네트워크 연결을 차단한다. LibreOffice에는 외부 연결·매크로·미지원 수식을 사전에 거른 사본만 전달한다. OS 전체 방화벽 격리까지 제공하는 구조는 아니다.
- 파일당 20MB, 동시에 8개, 문서당 18만 자·4천 텍스트 영역·6천 후보, 단일 영역 12,000자 검사. 내부 ZIP은 총 120MB·6천 항목까지. PDF 40쪽, 이미지 40개, 개별 이미지 2천만 화소. 시트당 사용 범위 10만 셀. 한도를 넘으면 일부를 누락한 정상 결과 대신 오류로 알린다.
- 파서/OCR/변환은 작업당 최대 3분. A 모델 시작·추론 제한은 기존 값을 유지한다. 작업 취소는 파서 자식 프로세스와 변환 도구를 정리하며, 이미 진행 중인 모델 호출은 반환/시간 제한을 기다릴 수 있다.

## 로컬 실행 도구

`requirements.files.lock.txt` → `.runtime/file-python`에 PyMuPDF 2.0, Pillow 12.3, lxml 6.1.3, openpyxl 3.1.5 등을 설치한다. 서버·모델 환경과 문서 처리 환경을 분리한다.

`scripts/prepare/prepare_file_tools.py`는 이번 연구에서 확인한 로컬 도구를 `.runtime/file-tools`로 준비한다. 앱 실행 중에는 연구 폴더 경로를 참조하지 않는다.

- LibreOffice 26.8.1.1 portable: 수식 강제 재계산. 독립 프로필의 `OOXMLRecalcMode=0`, 높은 매크로 보안 수준. 결과 오류·빈 캐시 모호성은 차단한다. 원본의 셀 스타일/메모는 원래 파일에서 가져오고 확인된 결과 값만 주입한다.
- Tesseract tessdata_fast 한국어·영어: 준비 시 고정 SHA-256 확인. Windows의 한글 경로 문제를 피하도록 작업 프로세스의 기준 폴더에서 상대 `tessdata` 경로 사용.
- hwplib 1.1.11 + Java 11 이상: 읽기 전용 HWP 어댑터. 이 PC에서는 JDK 26으로 확인했다.

다른 PC에 소스만 옮기면 위 선택 도구가 자동 다운로드되지는 않는다(받는 곳과 놓을 위치는 [외부 도구 설치 안내](file-tools.md)). 패키지 설치와 `file-tools` 준비가 필요하다. 없을 때 XLSX 수식/HWP는 준비 오류를 표시하고, 이미지 OCR은 실패 안내와 직접 가림을 제공한다. 설치형 EXE·자동 업데이트·타 PC 성능 보증은 이번 범위가 아니다. 오픈소스 재배포 시 PyMuPDF의 AGPL/상용 조건, LibreOffice/MPL·LGPL, hwplib/Apache-2.0, OCR 학습 데이터/Apache-2.0 등 각 배포물의 라이선스·고지 의무를 별도로 확인해야 한다.

## 검증 근거

`tests/test_file_review.py`, `scripts/check/check_file_feature.py`, `scripts/check/check_file_ui.cjs`, `scripts/check/check_file_desktop.py`에 재현 절차가 있다. 결과 파일은 `output/file-feature-validation/`에 보관한다.

- 실제 A 모델 + 합성 DOCX/PPTX/HWPX/XLSX/PNG/PDF: 읽기 → 선택 가림 → 새 파일 → 재열기 → 재검사 → 다운로드. HWP는 읽기 한계·저장 차단 확인. 원본 7개 SHA-256 불변.
- 백엔드 자동 시험 42개, 기존 가림 단위 시험 5개, 기존 게시글 화면 20개 흐름, 새 파일 화면 11개 흐름을 통과했다. 마지막 파일 목록 복원 변경 후 해당 API 시험과 화면 11개 흐름을 다시 통과했다. 실제 Windows 창의 사본 저장·종료 정리도 확인했다.
- 생성한 DOCX/PPTX/XLSX 사본을 별도 LibreOffice로 다시 열어 PDF로 렌더링했다. 이미지 이메일의 일부를 OCR이 놓치는 사례도 확인했으므로, 재검사 후보 0건만으로 가림 완료를 판단하지 않으며 실제 이미지 확인·수동 영역 가림을 제공한다.
- 일반 이름 김민수·이지은을 사용하고, 박하차는 일반 음료 문장에만 넣었다. 특정 실존 인물 자료를 사용하지 않았다.
- 파일 선택 UI·다중 선택·전환 후 상태 유지·직접 수정·이미지 드래그·재검사·실제 다운로드·390px 화면·시트/셀/숨김 셀을 확인한다.
- 실제 숨김 Windows WebView2 창에서 파일 열기/저장 API, 새 파일 저장, 원본 경로 거부, 종료 취소, 서버 종료 및 임시 사본 삭제를 확인했다. OS 선택 대화상자의 반환 경로만 시험용으로 고정했다.
- Word 메모·삭제 기록·문자 run 분리, Excel 표시 형식/메모/숨김/수식 실행 방지, CSV 인용 줄바꿈, ZIP 경로/엔터티 거부, PDF 글자층 삭제, 이미지 불투명 픽셀/메타데이터 제거, 저장 실패, 작업 취소 등을 자동 시험한다.
- 이 PC의 작은 합성 표본에서 정상 검사 1~11초, 사본 생성·재검사 1~6초 수준이었다. 첫 모델 준비와 문서 크기·이미지 수·PC 성능에 따라 늘어난다. 이 수치는 일반적인 정확도나 모든 파일의 처리 시간을 보장하지 않는다.

Microsoft Office·한컴의 모든 버전/기능, 대규모 실무 문서 전체, 모든 OCR 글꼴·배경을 검증하지 않았다. 안전하게 처리할 수 없는 구조의 지원을 넓히는 일과 A 모델의 오탐 개선은 후속 작업이다.
