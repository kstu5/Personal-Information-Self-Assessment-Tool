# 직접 수정 입력란이 보이지 않는 문제

2026년 10월 25일 사용자가 보고한 "버튼을 눌러도 입력란이 보이지 않음"을 실제 앱에서 재현했다. 대상은 합성 예시이며 기존 사용자의 열린 화면 선택은 별도 탭에 유지하고 시험 화면에서 확인했다.

## 원인과 변경

검출 목록을 스크롤한 상태에서 가림 방법을 직접 수정으로 바꾸면 입력란은 생성되지만 오른쪽 패널의 이전 스크롤 위치가 유지됐다. 재현 당시 입력란은 화면 위쪽 -158~ -123px에 있었고 커서는 문서 버튼에 남았다. 목록이 편집 이동을 요청해도 `chooseShown`이 두 번째 인자를 전달하지 않았다. 처리 버튼과 아래 적용 목록의 편집도 입력란 표시·포커스를 보장하지 않았다.

직접 수정 선택은 해당 후보 선택과 입력란 열기를 한 경로로 처리한다. 화면 갱신 후 입력란을 보이는 위치로 이동하고 커서를 넣어 기존 내용을 선택한다. 입력 중 다시 선택하지 않으며 기존에 지정한 직접 수정 항목을 눌렀을 때도 입력란을 보여준다. 이미지·PDF의 직접 수정 제한과 HWP의 읽기 전용은 유지한다. 백엔드 수정·저장 규칙은 변경하지 않았다.

## 실제 화면 확인

1. 검출 목록에서 이름의 가림 방법을 직접 수정으로 바꾼다. 수정 후 입력란은 높이 720px 창의 약 343~378px에 표시되고 실제 포커스가 입력란에 들어갔다.
2. 다른 후보를 선택한 뒤 아래 적용 목록의 편집을 누른다. 원래 수정 대상과 기존 입력값으로 돌아오며 입력란에 커서가 들어갔다.
3. 좁은 창(700px)에서 CSV의 후보를 고르고 처리 패널의 직접 수정 버튼을 누른다. 입력란이 높이 900px 창의 약 425~460px에 나타나며 입력할 수 있었다.

| 화면에서 직접 입력한 가상 파일 | 대체 문구 | 저장 사본 확인 |
|---|---|---|
| TXT 교육일정 메일 | 공개 담당자 | 실제 TXT에서 확인 |
| HWPX 참가협조공문 | 공개 운영담당 | 실제 ZIP 내부 XML에서 확인 |
| CSV 당첨자 명단 | 외부 담당자 | 실제 CSV에서 확인 |

세 파일 모두 실제 사본 생성·모델 재검사를 거쳐 다운로드한 바이트를 확인했다. 응답의 SHA-256과 다운로드가 일치하고 원본 해시가 유지됐다. 지정하지 않은 정보까지 제거했다는 의미는 아니다.

TypeScript 검사·빌드와 기존 관련 시험 11개를 통과했다. 위 스크롤·포커스 동작은 실제 브라우저에서 확인한 결과이며 단위 시험 11개가 스크롤을 자동 검증한다는 의미는 아니다. 상세 검증 요약·시험 사본·스크린샷은 `validation/qa/direct-edit-ui/`에 로컬 보관한다.
