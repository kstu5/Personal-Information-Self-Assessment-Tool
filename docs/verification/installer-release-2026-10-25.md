# Windows 설치판 배포 검증

일반 사용자가 직접 제작하는 방식에서, 개발자가 제작·검증한 EXE를 GitHub Releases에 올리는 방식으로 변경했습니다. 다운로드·소스 실행·개발자 제작 절차는 [README](../../README.md)와 [설치판 안내](../../installer/README.md)에서 구분합니다.

## 제작과 설치 구성

- 공식 Inno Setup 6.7.3 제작 도구의 Authenticode 서명을 확인한 뒤 사용했습니다.
- 배포 파일은 `PrivacySelfAssessmentTool-Setup-0.1.0.exe`와 SHA-256입니다. 약 2.1MB의 온라인 설치판이며 완전 오프라인 패키지가 아닙니다.
- Python·라이브러리·모델과 OCR·Java·LibreOffice·필요한 WebView2를 설치 중 준비합니다. 사용자는 Python·Node.js·JDK를 직접 설치하거나 화면을 빌드하지 않습니다.
- 명시한 실행 파일만 포함하고 개인 문서·연구 자료·상세 로그는 넣지 않습니다. 번들 화면의 React·React DOM 라이선스 고지와 사용자 안내를 포함합니다.
- 제거 과정의 `{app}` 전체 삭제를 없애 사용자가 별도로 저장한 자료까지 지우지 않도록 했습니다. 실행 환경 삭제·이동은 설치 폴더 경계와 junction 여부를 확인합니다.

## 확인한 범위

빈 로컬 시험 폴더에 실제 다운로드로 Python·패키지·모델·파일 도구를 준비했습니다. 여섯 단계가 모두 통과했습니다. WebView2는 시험 호스트에 이미 설치되어 있어 기존 설치 감지 경로를 확인했습니다.

[설치 환경 검사 도구](../../scripts/check/check_installed.py)는 설치 폴더의 Python으로 다시 실행하고 외부 Python 경로가 섞이지 않았는지 검사합니다. 고정 모델 해시, 게시글 이름·전화 검출, 예시 12종 읽기와 Word/PPT 페이지, TXT·CSV·TSV·HWPX 수정 사본 생성·재검사, 예시 원본 해시를 확인했습니다. 모두 통과했습니다.

배포할 EXE 자체도 `/VerifyInstall=1 /NOICONS`와 별도 빈 폴더를 사용해 설치했습니다. 여섯 단계가 끝나고 설치 종료 코드 0을 확인했으며, 기존 설치 등록을 전후 대조해 변경되지 않았음을 확인했습니다. 검증 모드는 제거 프로그램·설치 등록·바로가기를 만들지 않습니다. 따라서 일반 설치의 바로가기 생성과 기존 버전 업그레이드를 확인한 시험으로 확대 해석하지 않습니다.

이 EXE로 설치한 환경에서도 위 도구의 예시 12종·수정 사본 4종·모델·원본 보존 검사가 모두 통과했습니다. 배포 검사 요약은 이 실행 결과를 사용합니다.

설치한 패키지의 `pip check`에는 충돌이 없었고, 전용 창에 필요한 webview·CLR import도 통과했습니다. 창의 모든 사용자 조작을 자동 검증한 것은 아닙니다.

배포 EXE SHA-256: `2d7bd45886261a5a6ed4651d5742927726c571bf02b0ff6ba71cfbed7d7ab79d`.

상세 설치 로그·설치 사본은 `local-only/outputs/installer-runtime-check/`·`installer-exe-check/`, EXE·해시·검사 요약은 `installer/out/`에 생성하며 Git에서 제외합니다. Releases에는 개인 경로를 포함하지 않는 요약만 첨부합니다.

## 제한

현재 Windows 시험 호스트의 별도 설치 환경 검증입니다. 완전히 새 Windows 가상 머신, 모든 보안 정책·프록시·네트워크 오류·업그레이드·제거 시나리오, WebView2 미설치 PC에서의 신규 설치를 모두 검증한 것은 아닙니다. 개인정보 탐지 정확도를 새로 평가한 시험도 아닙니다.

설치 파일은 코드 서명되지 않았습니다. SHA-256 대조와 코드 서명은 서로 다른 확인입니다. 버전 태그로 자동 공개하는 워크플로는 추가하지 않고 검증한 파일을 직접 Releases에 배포합니다.
