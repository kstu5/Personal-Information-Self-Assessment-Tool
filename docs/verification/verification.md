# 1차 구현 검증 기록

> 이 문서는 모델 적용 전인 2026-10-16의 기록입니다. 2026-10-17 규칙 + atonlee/koelectra-ko-pii-ner 적용 후 검증은 [atonlee/koelectra-ko-pii-ner 적용 기록](../features/model-a-integration.md)을 참조하세요.

확인일: 2026-10-16. 대상: 현재 Windows x64 PC. 구현은 `src`, `backend`, `run.py`이며 기존 HTML 시안과 구분한다.

## 실행 결과

| 확인 | 결과 | 범위와 제한 |
|---|---|---|
| TypeScript 검사와 Vite 빌드 | 통과 | 배포용 정적 화면 생성 |
| Python 자동 시험 | 22개 통과 | 저장·복원·오류·실제 탐지·API 보호·시간 초과 |
| 화면 통합 시험 | 12개 흐름 통과 | 실제 엔진·실제 임시 파일 사용. OS 선택창만 경로 지정으로 대체 |
| Windows 전용 창 | 통과 | WebView2 화면 로딩, 파일 연결, 종료 보호·취소, 서버 정리 |
| VBS 실행 아이콘 경로 | 통과 | pythonw로 콘솔 없이 실행, 실제 프로그램 창 제목·핸들 확인, 동일 프로세스에서 가상 전화번호 탐지 성공 |
| 외부 요청 | 시험 중 없음 | 브라우저 외부 요청 감시. 백엔드 탐지는 ko-pii 코어 사용 |
| 서버 수신 주소 | 127.0.0.1 확인 | 다른 LAN 기기에서 직접 접속하는 시험은 미실행 |

Python 시험 중 Starlette의 httpx 시험 어댑터 사용 중단 예고 경고가 1건 있었다. 제품 실행 오류는 아니며 시험 도구 업데이트 시 교체 여부를 확인한다.

실행 경로 확인에서 발견한 두 문제를 수정했다. 콘솔이 없는 pythonw에서는 Uvicorn의 기본 콘솔 로그 설정을 사용하지 않도록 했고, 실행 도우미의 숨김 설정이 실제 프로그램 창까지 숨기지 않도록 분리했다. 수정 후 VBS 실행으로 “게시 전 · 개인정보 검토” 창이 나타났으며, `scripts/check/check_running_app.py`로 화면의 글을 바꾸지 않고 실제 검사 프로세스의 동작을 확인했다.

## 탐지 품질 관찰

`detection-evaluation.json`에 12개 가상 입력과 기대 구간, 실제 구간, 유형별 TP·FP·FN을 기록했다. 정확한 유형과 구간이 모두 일치한 입력은 8개였다. 소수의 설계용 예시이며 일반적인 정확도 추정치가 아니다.

이름의 문장 종결형을 놓치는 사례, 일반 단어를 이름으로 잡는 사례, 주소의 호수 누락, 문맥 없는 계좌번호를 다른 번호로 보는 사례가 남아 있다. 주소 평가는 호수까지 포함하는 구간을 정답으로 정의했으므로 부분 탐지는 완전 정답으로 계산하지 않았다.

부하 확인은 가상 전화번호가 반복된 19,000자에서 후보 1,000개를 약 0.4초에 반환했다. 현재 PC의 한 가지 입력에서 측정한 값으로 모든 글이나 저사양 PC의 성능을 보장하지 않는다.

## 다음 사용 확인

실제 Windows 파일 선택 창에서 원하는 폴더를 고르고, 같은 이름의 파일을 저장할 때 확인창을 검토한다. 저장한 뒤 프로그램과 PC를 재시작해 다시 불러온다. 행사 모집·안내·결과 공지 및 커뮤니티 글을 대표하는 평가 표본을 확장해 탐지 품질과 색상 가독성을 확인한다.

## 커뮤니티 가상 게시글 3종 추가 점검

2026-10-16에 독서 모임 모집, 중고거래와 나눔, 취미 커뮤니티 후기 글을 각각 작성했다. 실행 전에 원문과 기대 항목을 `research/community_cases_v1.json`에 고정하고 실제 `/api/check` 경로로 검사했다. 이 표본은 취약점 탐색용이며 대표 정확도 평가 자료가 아니다.

기대 항목 16개 중 완전 탐지 9개, 부분 탐지 2개, 유형 오분류 1개, 미탐 4개를 확인했다. 기대 항목 밖의 추가 오탐은 10곳이고 실제 후보는 총 22곳이다. 상세 주소 2개는 번지 뒤가 누락됐으며 이름과 한글 숫자 전화번호에서 미탐이 있었다. 물건의 규격과 일반 명사를 개인정보로 분류하는 사례도 확인했다. 반면 변형 이메일과 공백 또는 구분자 없는 전화번호는 해당 글에서 찾았다.

제공한 작업 파일 3개를 별도 시험 브라우저의 실제 빌드에서 열어 원문 보존, 실제 API 결과 일치, 색상·목록·건수, 원문 위치 이동, 재검토 안내를 확인했다. 선택 창만 시험 파일 선택으로 대체했다. 브라우저 외부 요청과 JavaScript 오류는 없었다. 제품 탐지 규칙과 UI 코드는 변경하지 않았다.

원문·전체 후보·판정과 재현 자료는 `output/community-review`에, 8쪽 보고서는 `output/pdf/커뮤니티_게시글_3종_개인정보_탐지_점검보고서_v1.pdf`에 저장했다. 재실행 도구는 `scripts/evaluate/evaluate_community_cases.py`, `scripts/check/check_community_ui.cjs`다.
