# 원본·적용 미리보기와 처리 지정 표시

2026년 10월 25일 가상 이력서 DOCX·PDF와 배송 명단 XLSX를 실제 앱에서 검사한 결과로 화면 동작을 확인했다. 기존 문서 페이지 기능에 즉시 비교와 처리 상태 표시를 추가했다.

## 동작

원본/적용 미리보기 토글은 가림 선택을 바꾸거나 사본을 생성하지 않는다. 처리 방법을 지정하면 적용 미리보기로 전환하고 원본으로 돌아와도 선택은 유지된다. 문서의 체크, 목록 배경·상태 배지, 처리 지정/미설정 개수로 지정 여부를 표시한다. 명시적 유지와 미설정을 구분하고 취소 시 체크·상태·미리보기를 함께 되돌린다. 일괄 선택 체크박스와 처리 지정 상태도 문구로 구분한다.

| 화면 | 원본 | 적용 미리보기 |
|---|---|---|
| Word·PPT 페이지 | 원본 이미지와 처리 지정 체크 | 문맥으로 연결한 원본 위치에 가림·대체 문구를 겹친 간이 화면 |
| PDF·이미지 | 원본 이미지, 직접 영역은 점선 | 선택한 부분/전체 가림과 직접 영역을 검은색으로 표시 |
| 텍스트·Excel 셀 | 원문 내용과 처리 지정 체크 | 선택 위치의 대체 내용 또는 영역 전체 수정 내용 |

## 확인 결과

- 이력서의 첫 이름 부분 가림, 첫 전화 전체 가림, 첫 이메일 `공개 문의창구` 수정이 즉시 표시됐다. 선택하지 않은 반복 이름·전화·이메일은 바꾸지 않았다.
- 원본 전환 시 변경 표시가 없어지고 처리 지정 체크 3개는 유지됐다. 다시 적용 화면으로 바꾸면 세 변경이 복원됐다.
- 이메일의 처리 선택 취소 시 미설정으로 돌아가고 변경 표시·체크가 각 1개 줄었다. 다시 수정할 수 있었다.
- 생년월일의 명시적 가리지 않음은 별도 유지 배경과 체크로 표시되며, 원래 내용은 유지됐다. 미설정 상태에서는 네 처리 버튼이 모두 선택되지 않았다.
- PDF는 전체 가림 선택 시 불투명 가림 1개, 원본 전환 시 0개이며 처리 체크는 유지됐다. 직접 수정은 계속 비활성이다.
- Excel B6의 부분 가림은 적용 화면의 `김**`, 원본 화면의 `김도윤`으로 전환됐고 선택은 유지됐다.
- 700px 화면에서는 문서와 처리 패널을 세로로 표시했다. 전체 너비는 685px로 가로 넘침이 없고, 적용 토글과 처리 체크가 유지됐다.
- TypeScript 검사·화면 빌드, 기존 가림 시험 5개와 새 미리보기 시험 4개를 통과했다. 새 시험은 UTF-16 위치·반복 값, 원본 보존, 유지/취소, 영역 전체 수정의 우선 처리·빈 수정 내용, 서버의 부분 가림 값·사용자 입력을 확인한다.

## 제한과 부담

토글을 위해 별도 백엔드 처리·변환·모델 재검사를 추가하지 않고 화면에서 즉시 비교한다. 실제 파일 생성·재검사는 기존 버튼으로 실행한다. 원본 데이터와 수정 API의 선택 식별자는 유지한다.

Word·PPT 페이지의 간이 미리보기는 원본 위치에 표시하므로 긴 대체 문구는 잘려 보일 수 있고 줄바꿈·배경·서식이 실제 사본과 다르다. 화면 위와 아래에 이 제한을 안내한다. 모호한 위치·페이지 밖 정보·영역 전체 수정은 확정 위치처럼 덮어쓰지 않는다. 영역 전체 수정이 있으면 적용 화면 전환 시 텍스트 보기로 안내한다. 최종 배치는 사본 생성 후 실제 사본 화면에서 확인한다. 미리보기는 개인정보 제거 보증이나 검출 정확도 측정이 아니다.

화면 캡처는 로컬 전용 `test/qa/visual-review/ui/`에 보관하고 코드·시험·이 보고서는 Git 관리 대상으로 둔다. GitHub 업로드는 별도 작업이다.
