# 파일 검사 목록과 미리보기 확인

2026년 10월 25일. 실제 앱의 로컬 서버와 atonlee/koelectra-ko-pii-ner 모델을 사용해 합성 문서로 확인했다. 모델이나 API를 가짜 응답으로 대체하지 않았다. 이번 변경은 검토 화면과 안내를 대상으로 하며 탐지 규칙이나 가림 엔진을 바꾸지 않았다.

## 입력과 확인된 미리보기

| 합성 입력 | 실제 후보 수 | 확인한 표시 |
|---|---:|---|
| [이력서 DOCX](../../examples/documents/이력서_검사예시.docx) | 14 | 텍스트·위치와 선택 후보의 강조 표시 |
| [당첨자 XLSX](../../examples/documents/추첨당첨자_명단예시.xlsx) | 33 | 셀 표, 내부 배송정보 시트의 숨김 표시와 이름·전화·이메일·주소 |
| [이력서 PDF](../../examples/documents/이력서_검사예시.pdf) | 29 | 실제 원본 페이지와 가림 후 사본 페이지 |

후보 수는 정확도나 정답 수가 아니다. PDF는 OCR과 글자층이 같은 정보를 각각 검출할 수 있다. 정답은 [별도 확인 목록](../../examples/documents/검사_확인목록.md)과 비교한다.

## 화면에서 확인한 동작

- 이력서는 심각 0·높음 8·보통 4·낮음 1·참고 1개로 나타났고, 위험도 카드를 누르면 해당 목록만 표시됐다. 전체 목록은 높은 위험도부터 묶였다.
- 높음 필터에서 김민수를 검색해 두 항목을 선택하고 부분 가림을 적용했다. 두 변경 예정 값이 김**로 표시됐다. 하나의 선택을 해제하면 전체 선택 상자가 중간 상태가 됐다.
- 검색어를 유지하고 다른 위험도를 고르면 0건 안내와 필터 밖 선택 개수가 나타났다. 전체 목록 보기는 검색과 위험도 필터를 함께 초기화했다. 대소문자가 다른 MINsu 검색으로 이메일 두 곳도 찾았다.
- 이름 하나를 직접 수정으로 전환해 [지원자]를 입력했고 목록과 본문 미리보기에 반영됐다. 원문 위치 선택은 해당 텍스트 영역을 강조하고 이동했다.
- Excel의 내부_배송정보를 선택해 숨김 시트에 있는 세 사람의 배송정보와 셀 주소가 표시되는 것을 확인했다. 셀 표는 원래 Excel의 서식과 인쇄 배치를 그대로 재현하는 화면이 아니다.
- PDF 후보 전체에 가림을 선택하고 실제 사본을 생성·재검사했다. 실제 사본 확인에서 가려진 개인정보 위치가 검은 영역으로 표시됐다. 재검사에 남은 후보 한 개도 표시됐다. 내려받기나 원본 덮어쓰기는 수행하지 않았다.
- 1280px 화면과 390px 화면에서 배치를 확인했다. 좁은 화면에서는 위험도 카드가 줄을 바꾸고 페이지 전체에 가로 넘침이 생기지 않았다. 파일 목록과 셀 표의 내부 가로 스크롤은 유지했다.
- TypeScript 검사와 배포용 화면 빌드, 기존 가림 단위 시험 5개가 통과했다. 같은 작업에서 앞서 실행한 Python 회귀 시험 54개도 통과했으며 이후 백엔드는 변경하지 않았다.

화면 캡처와 상세 실행 자료는 `local-only/`에 보관한다.

## 지원 범위와 후속 점검

Word·HWPX·PowerPoint·HWP의 원래 페이지 배치를 보여주는 미리보기는 현재 제공하지 않는다. 읽어 낸 글자와 위치, 지원하는 내장 이미지로 확인하며 원래 문서 프로그램에서도 사본을 열어 배치를 확인해야 한다. 이번 실제 화면 시험은 DOCX·XLSX·PDF 세 형식에 한정했다.

이력서 작성일 2026년 10월 25일을 생년월일로 분류하는 기존 오탐을 확인했다. PDF 가림 사본 재검사에서는 글자층의 th를 성명으로 잡은 후보 한 개가 남았다. 이 두 사례는 후속 탐지 품질 점검 대상으로 남긴다. 후보가 남았다는 사실이나 반대로 0건이라는 사실만으로 사본의 개인정보 제거 여부를 판단하지 않는다.
