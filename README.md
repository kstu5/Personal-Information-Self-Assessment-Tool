# 개인정보 자가진단 도구

게시글·문서·이미지를 공유하기 전에 개인정보와 인증정보 후보를 찾고, 원문을 확인하며 가리거나 수정하는 **Windows용 로컬 프로그램**입니다.

**배포 버전: 0.1.4** · 검출 목록 정리 → 가림·수정 → 원본과 비교 → 사본 생성·재검사

**0.1.4는 게시글 검토 기능·화면 통일, 사용자 추가 항목의 유형 지정, 게시글·파일 자동 가림, 문서 페이지에서 직접 글자 선택, HWP 5 수정 사본 저장을 제공합니다.** 이전 버전에서 작업을 저장하고 앱을 종료한 뒤 새 설치 파일로 업데이트하세요.

검사는 PC 안에서 수행합니다. 문서 파일은 원본에 덮어쓰지 않고 새 사본으로 저장합니다. **자동 탐지에는 오탐과 누락이 있으므로, 공유 전 수정 사본을 직접 확인하세요.**

## 설치와 업데이트

1. 이전 버전을 사용 중이라면 필요한 작업을 저장하고 앱을 종료합니다.
2. 설치 EXE를 실행하고 설치 폴더를 선택합니다.
3. 인터넷에 연결한 상태로 설치가 완료될 때까지 기다립니다.
4. 시작 메뉴의 **개인정보 자가진단 도구**를 실행합니다.

**Windows x64 온라인 설치판**입니다. Python·탐지 모델·OCR·Java·LibreOffice와 필요한 WebView2를 설치 중 준비하므로 인터넷 연결과 충분한 디스크 공간이 필요합니다. 사용자가 Python·Node.js·JDK를 따로 설치하거나 소스를 빌드할 필요는 없습니다. 설치 이후 개인정보 검사는 외부 생성형 AI API로 문서를 보내지 않고 PC 안에서 수행합니다.

기본 설치 위치는 `%LOCALAPPDATA%\Programs\BeforePost`이며 설치 화면에서 바꿀 수 있습니다. 구성요소의 긴 경로 오류를 피하도록 **설치 폴더의 전체 경로는 100자 이하**로 지정합니다. `BeforePost`는 기존 설치와 호환되는 내부 폴더 이름입니다.

설치에 실패하면 설치 폴더의 `install.log`에서 실패 단계를 확인하세요. 로그를 공유할 때는 개인 경로 등 불필요한 정보를 지우세요.

## 사용 방법

### 파일 검사

| 단계 | 할 일 |
|---|---|
| **1. 파일 추가** | **파일 검사 → 파일 추가**, 또는 탐색기의 파일을 검사 화면에 드래그 앤 드롭합니다. 여러 파일을 함께 추가할 수 있으며 폴더는 지원하지 않습니다. |
| **2. 검출 목록 정리** | 원문 위치를 확인해 오탐을 제외하고, 원문 검색이나 글자 드래그로 누락된 항목을 추가합니다. |
| **3. 가림·수정과 비교** | 남은 후보에 처리 방법을 지정하고 **원본 / 적용 미리보기**로 비교합니다. |
| **4. 사본 생성·재검사** | **사본 생성·재검사 → 실제 사본 확인**을 실행합니다. 남은 후보와 가림 범위를 확인한 뒤 확인란을 체크하고 새 파일로 저장합니다. |

검사 중에는 대기·내용 읽기·개인정보 검사·검토 준비 상태를 표시하며 **작업 취소**로 중지할 수 있습니다. 파일 추가는 설치판에서 Windows 기본 선택 창을 사용합니다. 소스의 브라우저 실행에서도 지원되는 경우 운영체제 파일 선택 기능을 우선 사용합니다.

**목록 정리와 범위 선택**

- **오탐 제외:** 한 곳·여러 곳·현재 검색 목록 전체를 선택해 **선택 후보 제외**를 누릅니다. 해당 위치는 가림 대상에서 빠지고 원문은 유지됩니다.
- **누락 항목 검색:** **원문에서 누락 항목 검색·추가**에서 문구를 검색하고, 결과를 한 곳·여러 곳·전체 선택해 사용자 후보로 추가합니다. **위치 보기**에서 원문과 범위를 확인할 수 있습니다.
- **직접 범위 선택:** 원본의 후보는 클릭하고 원하는 글자는 드래그합니다. **한 문단·셀 안에서** 선택한 범위를 목록에만 추가하거나 가림·직접 수정으로 연결합니다. 기존 후보는 **글자 범위 변경**으로 다시 지정할 수 있습니다.
- **파일 일괄 적용:** **현재 파일 후보에 일괄 적용**은 검색·위험도 필터와 관계없이 **미설정 후보**를 처리합니다. 기존 개별 지정·영역 직접 수정은 유지하며, 일괄 적용만 되돌릴 수 있습니다. 직접 지정한 이미지 가림 영역과 겹치는 후보는 화면 안내에 따라 개별 확인하세요.

제외한 위치가 다시 필요하면 원문에서 새 항목으로 추가합니다. 이전 가림 설정을 복원하지 않습니다. 제외·추가는 **현재 파일의 위치에만 적용**하며 다른 파일이나 전역 탐지 기준에 학습하지 않습니다. **0.1.4에서는 추가할 정보 유형을 선택**할 수 있고, 추가 후 **사용자 추가 유형**에서 바꿀 수도 있습니다. 유형 미지정은 참고에 남으며, 유형을 선택하면 해당 유형의 기본 위험도와 가림 기준을 사용합니다. 이는 사용자 지정이며 모델의 확정 판정이나 유효성 검증이 아닙니다. 추가만으로 가리지는 않으며, 기존 항목의 유형 변경은 현재 가림 선택을 유지합니다.

검색은 대소문자·띄어쓰기가 같은 문구를 문단·셀별로 찾습니다. 문단 경계를 넘는 문구나 OCR가 읽지 못한 글자는 검색되지 않습니다. 활성 후보와 겹치는 범위는 중복 추가하지 않습니다. 영역 직접 수정 중인 문단은 해당 수정을 취소한 뒤 글자 범위를 선택하세요.

**0.1.4에서는 Word·PPT·PDF·이미지 페이지의 글자를 바로 드래그**해 선택합니다. 원본 위치에 파란 선택 표시와 확인창을 보여주며, **목록에만 추가·부분 가림·전체 가림·직접 수정** 중 지원되는 동작을 선택할 수 있습니다. 기존 후보를 클릭한 뒤 **글자 범위 변경**을 누르면 같은 페이지에서 다시 드래그할 수 있습니다. 적용 미리보기에서는 새 범위를 지정하지 않으며 원본으로 전환해 선택합니다.

페이지와 원문 문단·글자 위치가 확인된 범위만 연결합니다. 반복 문구의 연결이 모호하거나 내장 이미지가 회전·잘림 등으로 대응되지 않으면 **원문 텍스트로 선택** 또는 원본 이미지 화면에서 확인합니다. OCR 미인식 부분은 이미지의 **직접 영역 가리기**로 보완하세요. HWP 5도 본문에서 검토 범위를 추가·변경하고 가림 사본을 저장할 수 있습니다.

### 개인정보 자동 가림

게시글·파일을 검사하고 검출 목록을 정리한 후 **개인정보 자동 가림**을 누르면 **일부 정보 확인용** 기준과 적용 예정 수를 보여줍니다. **기준대로 적용**하면 처리 결과 또는 적용 미리보기에서 결과를 확인하고 후보별로 바꿀 수 있습니다. 버튼을 누르기 전에는 이 기준을 적용하지 않으며, 사본 생성·저장도 별도로 진행합니다.

| 유형 | 자동 가림 기준 |
|---|---|
| 성명 | 첫 글자만 유지: `김민수` → `김**` |
| 전화·팩스 | 앞자리와 끝 4자리 유지: `010-0000-1234` → `010-****-1234` |
| 이메일 | 계정 첫 글자와 도메인 유지 |
| 주민·외국인등록번호 | 앞 6자리 유지 |
| 운전면허·여권번호, API 키·비밀번호 | 전체 가림 |
| 계좌·카드번호 | 끝 4자리 유지 |
| 생년월일·나이 | 출생연도·10세 단위 연령대. 10세 미만은 `10세 미만` |
| 주소 | 읽어낸 시·군·구까지만 유지. 행정구역 경계가 불확실하면 전체 가림 |
| 차량번호·사번·보험번호·처방번호 | 현재 게시글·파일에서 같은 값에 같은 대체 표시: `차량 A`, `사번 A` 등 |
| 국적·학력·전공·직책·키·체중, 우편·필지번호, 사용자 추가 범위 | 전체 가림 후 필요한 경우 개별 변경 |
| 사건·민원·문서번호, 사업자·법인번호, 약품코드, URL | 개인·사건과 연결되는지 직접 확인하도록 남김 |
| IP와 그 밖의 후보 | 전체 가림 |

검색·위험도 필터와 관계없이 **현재 게시글 또는 파일**을 대상으로 합니다. 사용자가 지정한 가림·유지·수정과 문단·셀 직접 수정은 보존하며, 초기 자동 기본값은 위 기준으로 바꿉니다. 제외한 후보는 적용 대상에서 빠집니다. 직접 지정한 이미지 가림 영역과 겹치는 후보는 따로 확인합니다. **자동 가림 되돌리기**는 직전 자동 적용을 취소하되 이후 개별 변경한 항목을 유지합니다.

PDF·내장 이미지에서는 출생연도·주소 축소·대체명처럼 문구 교체가 필요한 항목을 **전체 영역 가림**으로 처리합니다. PNG·JPG·JPEG 문구 교체는 기존 글꼴·공간·겹침 검증을 거칩니다. 형식이 불확실한 날짜·나이·번호는 전체 가림으로 처리합니다.

이 기능은 **익명화를 보장하지 않습니다.** 생년월일 앞자리·전화 끝자리·이메일 도메인 등 남긴 정보와 문맥으로 신원을 추측할 수 있습니다. 대체 표시는 같은 원문 값만 연결하며 동일 인물 여부를 판단하지 않습니다. 자동 탐지의 오탐·누락을 해결하는 기능이 아니므로 원본과 실제 수정 사본을 확인하세요. 추가 모델이나 외부 API는 사용하지 않습니다.

### 게시글 검사

제목과 본문을 입력하거나 **저장한 글 불러오기**에서 `.piipost`를 연 뒤 검사합니다. 후보별 처리 방법을 선택하고 수정한 글을 이어 쓰거나 작업 파일로 저장합니다.

**게시글 검토 흐름**

게시글은 파일 검사와 **같은 위험도 요약 화면**을 사용하며, **왼쪽 원본·적용 미리보기 / 오른쪽 선택 항목 편집과 검출 목록**으로 확인합니다. 편집과 목록은 탭으로 나누지 않고 함께 표시합니다. 위험도 카드나 처리 상태 요약으로 목록을 좁힐 수 있습니다. 원문 후보의 체크 표시는 **처리 방법을 지정했다는 뜻**이며 저장·검토 완료를 의미하지 않습니다. 자동 검출의 위험도는 원문 기준이고, 사용자가 유형을 지정한 항목에는 해당 유형의 기본 위험도를 표시합니다. 좁은 화면에서는 원문과 도구가 위아래로 배치됩니다.

1. **검출 목록 검색·필터:** 내용·유형·위치를 검색하고 위험도를 선택합니다. **원문 위치**로 이동해 해당 한 항목을 편집할 수 있습니다.
2. **오탐 제외:** 개별 후보나 검색·필터 결과에서 선택한 후보를 제외합니다. 해당 위치의 원문은 유지되고 자동·전체 선택 가림 대상에서는 빠집니다.
3. **누락 항목 검색·추가:** 원문에서 정확히 일치하는 문구를 검색해 한 곳·여러 곳·추가 가능한 결과 전체를 선택합니다. **추가할 정보 유형**을 고른 뒤 추가하면 해당 유형에 표시하며, 고르지 않으면 참고·사용자 추가로 남습니다. 제목과 본문은 별도로 검색하고 같은 문구도 위치별로 추가합니다. 추가만으로 가리지 않습니다.
4. **원문 드래그 범위 지정:** **원본** 화면에서 글자를 드래그하고 유형을 선택해 검토 목록에 추가하거나 바로 부분·전체 가림·직접 수정을 선택합니다. 기존 후보의 **글자 범위 변경**으로 범위를 조정할 수 있습니다. **적용 미리보기**에서 추가하려면 **누락 항목 추가 / 원본에서 계속 추가**를 누릅니다. 추가 후에는 원본으로 돌아가 다른 위치를 계속 선택할 수 있습니다. 제목과 본문을 한 범위로 묶을 수 없고 다른 활성 후보와 겹치는 범위는 조정하거나 해당 후보를 먼저 제외해야 합니다.
5. **기준에 따른 자동 가림:** 파일 검사와 같은 **일부 정보 확인용** 기준을 제목·본문에 적용합니다. 검색·위험도 필터와 관계없이 현재 게시글의 남은 후보를 대상으로 하며, 사용자가 지정한 처리·직접 수정·제외는 유지합니다. 원문과 처리 결과를 비교하고 필요하면 자동 가림을 되돌리세요.

제외한 내용은 별도 복원 대신 원문에서 새 후보로 추가합니다. 새 항목은 이전 가림 설정을 가져오지 않습니다. 범위 변경도 새 사용자 후보로 시작하며 **목록에만 추가**하면 미설정으로 남습니다. 검토 목록 변경 후에는 이전 처리의 일반 되돌리기 이력을 비워 제외한 항목이 다시 섞이지 않도록 합니다. 이 작업은 현재 검토에만 적용되며 다른 게시글이나 탐지 기준에 반영하지 않습니다. 저장 파일에는 처리 결과의 제목·본문이 들어가며, 추가·제외 목록이나 가림 선택 이력은 저장되지 않습니다. 다시 불러와 검사하면 후보는 새로 탐색됩니다.

제목은 **300자**, 본문은 **30,000자**까지 검사합니다. `.piipost`는 제목·본문을 담은 암호화되지 않은 JSON이며 **파일 검사에서 사용하는 문서 형식이나 가림 상태 백업이 아닙니다.** 앱 종료·화면 새로고침 전에 필요한 작업과 사본을 저장하세요.

### HWP 5 수정 사본

HWP 본문·표·머리말·꼬리말·각주·도형 안의 지원 텍스트를 **원본 구역·문단·글자 구간에 연결**합니다. 선택한 위치에 부분·전체 가림이나 직접 수정을 적용하고 **사본 생성·재검사 → 새 파일로 사본 저장**으로 `.hwp` 파일을 만듭니다. 원본은 보존하며, 내장 이미지는 OCR 글자 선택이나 직접 영역 지정으로 가립니다. 한글 프로그램을 별도로 설치하지 않아도 동작하며 기존에 포함된 Java·hwplib를 사용합니다.

선택하지 않은 기록은 유지하고, 변경한 글자의 위치·서식 참조와 문단 글자 수를 갱신합니다. 표·문단·글꼴·개체 기록을 보존하며 수정 문단의 오래된 줄 배치 캐시는 제거해 한글에서 다시 계산하도록 합니다. **긴 문구는 줄바꿈·쪽수가 달라질 수 있으므로 모든 문서의 배치가 동일하다고 보장하지 않습니다.** 앱 화면은 원본 문단 순서를 재구성한 내용이며 실제 HWP 쪽 배치와 다릅니다.

사본은 기존 파일에 덮어쓰지 않고 새 저장 구조로 작성합니다. 미리보기 텍스트·이미지, 요약 속성·저장 이력·스크립트·외부 연결 설정과 전자서명은 유지하지 않습니다. 지원 내장 이미지는 가림 영역의 원문 픽셀을 제거한 PNG로 다시 저장하고 원래 이미지 데이터와 메타데이터를 남기지 않습니다.

저장 후 파일을 다시 읽어 **선택한 원본 위치의 변경 텍스트**, 저장할 기록·이미지 데이터, 제거한 부가 기록을 확인하고 hwplib로 독립 읽기를 수행한 뒤 사본을 제공합니다. 가리려는 문구가 별도 연결·개체 기록에도 남아 제거를 확인하지 못하면 저장을 중단합니다. 이 검증은 선택한 수정의 확인이며 개인정보 탐지의 누락이나 익명성을 보장하지 않습니다.

**지원 제한:** 암호화·DRM·배포 제한 문서, 변경 추적 내용·작성자 기록, 외부 그림, 첨부·OLE·미지원 이미지 데이터는 처리 또는 저장이 제한됩니다. 필드 결과처럼 다시 채워질 수 있는 글자 구간은 검토 목록에서 수정 제한 이유를 표시하고 자동 가림에서 제외합니다. 필요한 내용을 일반 텍스트·포함된 그림으로 정리하고 변경 사항을 확정한 사본을 사용하세요.

### 가림 방법과 기본 설정

| 방법 | 동작 |
|---|---|
| 부분 가림 | 유형별로 일부를 남깁니다. 예: `김**`, `010-****-2103`. 인증정보는 부분 가림을 선택해도 전체를 숨깁니다. |
| 전체 가림 | 텍스트는 표시 글자마다 `█` 한 개로 바꿉니다. 예: `김도윤` → `███`. 공백·줄바꿈을 유지하고 이모지·결합 문자는 보이는 한 글자로 셉니다. |
| 직접 수정 | 선택한 위치의 내용을 입력한 문구로 바꿉니다. 지원되는 형식에서 사용할 수 있습니다. |
| 가리지 않음 | 해당 후보의 원문을 유지합니다. |

자동 검출 후보의 API 키·인증 토큰·비밀번호에는 **전체 가림**, 주민등록번호·외국인등록번호·운전면허번호·여권번호에는 **부분 가림**을 기본 지정합니다. 표준 주민·외국인등록번호는 앞 6자리 숫자를, 운전면허·여권번호는 첫 글자를 남깁니다. 그 밖의 유형과 사용자가 목록에만 추가한 항목은 직접 선택하며 **미설정 항목은 원문 그대로 남습니다.**

검출 목록의 선택 처리는 **현재 검색·위험도 필터에 보이는 선택 항목**에 적용합니다. 파일 일괄 적용과 대상 범위가 다르므로 처리할 항목 수를 확인하세요. 제외해도 별도로 지정한 이미지 가림 영역이나 영역 직접 수정은 남습니다. 사본 재검사는 새 파일을 검사하므로 제외했던 정보가 다시 후보로 나올 수 있습니다.

### 이미지의 가림과 직접 수정

독립된 **PNG·JPG·JPEG**는 원문 픽셀을 지운 뒤 부분 가림 문구·`비공개` 표시·직접 입력한 문구를 다시 씁니다.

1. 이미지를 검사하고 후보를 선택합니다.
2. **부분 가림**, 전체 가림에 해당하는 **비공개 표시**, 또는 **직접 수정 → 바꿀 내용**을 선택합니다.
3. **적용 미리보기**에서 문구와 주변 글자·표 선을 확인합니다.
4. 사본 생성·재검사 후 실제 결과를 확인하고 **PNG 사본**으로 저장합니다. JPG·JPEG 입력도 PNG로 출력합니다.

직접 수정은 **줄바꿈 없이 80자 이하**이며 빈 문구는 원문을 지웁니다. 원래 글자 높이를 기준으로 크기를 추정하고 같은 줄의 빈 공간을 활용합니다. 좁은 폭에 맞춰 글자를 작게 줄이지 않습니다. 일반 특수문자·체크·이모지는 로컬 글꼴이 지원하는 범위에서 표시합니다.

공간 부족·미지원 문자·수정 영역 겹침이 있으면 경고를 표시하고 사본 생성을 중단합니다. 오류 영역은 원문으로 남거나 오류 안내와 함께 원본이 표시될 수 있으므로, 미리보기가 보인다는 것만으로 수정 완료로 판단하지 마세요. 글꼴·사진·복잡한 배경은 원본과 다르게 보일 수 있습니다.

**직접 영역 가리기**는 사각형을 그린 뒤 확대 화면에서 확인하고 모서리를 조정해 **이 영역 가림 적용**으로 확정합니다. 모서리는 방향키로도 조정하며 Shift를 누르면 10픽셀씩 움직입니다. **검출 표시 보기**로 위치 표시를 켜고 끌 수 있습니다. 미리보기와 저장은 같은 이미지 처리를 사용하며 수정 이미지의 메타데이터는 제거합니다.

PDF 페이지와 DOCX·PPTX·HWPX·HWP 5의 지원 내장 이미지는 **검은 영역 가림**을 사용합니다. 이 경우 문구 교체는 지원하지 않으며, 부분 가림도 별표를 새로 쓰는 대신 해당 글자의 영역을 검게 지웁니다.

## 지원 파일과 제한

| 형식 | 확인 화면 | 드래그 범위 지정 | 수정·저장 범위 |
|---|---|---|---|
| TXT | 읽어낸 내용·위치 | 내용·텍스트 화면의 글자 선택 | 선택 가림·문구 수정, UTF-8 사본 |
| CSV·TSV | 행·열·빈 셀을 유지한 표 | 한 셀 안의 글자 선택 | 셀 내용 가림·수정, UTF-8 BOM 사본 |
| DOCX·PPTX | 변환한 문서·슬라이드 페이지, 텍스트·위치 | 문서 페이지에서 직접 글자 선택 | 지원 텍스트·부가 정보 수정. 메모·노트·속성도 별도 확인 |
| HWPX | 추출 본문을 재구성한 내용 | 내용·텍스트 화면의 글자 선택 | 지원 XML 텍스트·부가 정보 수정. 원래 쪽·표 배치 재현은 미지원 |
| HWP 5 | 원본 기록과 연결한 본문·지원 내장 이미지 | 본문 글자 선택·이미지 영역 지정 | 지원 텍스트·이미지 가림, HWP 사본 저장 |
| XLSX | 셀·숨김 영역·메모·속성 | 한 셀 안의 글자 선택 | 지원 수식 재계산 후 **값 전용 사본**으로 가림·수정 |
| PDF | 실제 페이지, 글자층·OCR 위치 | 페이지에서 직접 글자 선택·사각형 선택 | 선택 영역의 글자·픽셀 삭제 후 가림. **문구 교체 미지원** |
| PNG·JPG·JPEG | 실제 이미지·OCR 위치 | 이미지에서 직접 OCR 글자 선택·사각형 선택 | 부분 가림·비공개 표시·문구 수정·영역 가림, PNG 출력 |

글자 범위는 **원본 탭의 같은 문단·셀·OCR 행 안에서만** 선택합니다. 문단·셀을 가로지르는 범위는 나누어 추가하세요. 페이지의 선택 위치는 원문 글자 위치로 검증하며 화면 좌표를 원문 수정 위치로 그대로 사용하지 않습니다. 페이지 화면은 변환 결과이므로 원래 프로그램의 배치와 다를 수 있고, 텍스트 위치 화면도 계속 이용할 수 있습니다.

### 처리 한도

| 항목 | 한도 |
|---|---|
| 파일 크기·열린 파일 수 | 파일당 20MB · 동시에 8개 |
| 이미지 | 2천만 화소 이하 · 파일에서 읽어내는 이미지 최대 40개 |
| PDF 검사 | **파일 전체 40쪽 이하** |
| DOCX·PPTX 페이지 화면 | 처음 40쪽 표시. 다른 읽기 제한을 넘지 않았다면 이후 내용은 텍스트·위치에서 확인 |
| XLSX | 시트당 사용 범위 10만 셀 이하 |
| 게시글 | 제목 300자 · 본문 30,000자 |

이 한도는 로컬 PC의 메모리 사용과 처리 시간을 제한하기 위한 기준입니다. 추출 텍스트·개체 수·처리 시간에도 제한이 있어, 위 조건 안의 파일도 구조에 따라 검사나 사본 저장이 제한될 수 있습니다.

### 미리보기·저장 시 확인할 점

- **원문과 OCR 구분:** DOCX·PPTX·HWPX·HWP 5 본문과 정상 PDF 글자층은 직접 읽고, 지원되는 이미지 영역은 OCR로 보완합니다. XLSX 그림은 검사 범위에 포함되지 않습니다. 
- **화면 밖 정보:** 메모·발표자 노트·작성자·문서 속성·숨김 영역은 본문 페이지에 보이지 않을 수 있습니다. **텍스트 · 위치**도 함께 확인하세요.
- **배치 차이:** Word·PPT 저장 전 문구 미리보기는 실제 사본과 줄바꿈·배치가 다를 수 있습니다. HWP/HWPX 내용 화면은 원래 쪽·표·글꼴을 재현하지 않습니다. 페이지 변환이 실패해도 텍스트·위치에서 계속 검토할 수 있습니다.
- **PDF:** 주석·링크·양식·서명·첨부·회전된 페이지 등이 있으면 검사만 가능하며 사본 생성을 제한합니다. 저장 가능한 PDF도 페이지를 새 문서로 복사하므로 목차·기본 문서 속성·접근성 태그 등은 보존하지 않습니다.
- **XLSX:** 그림·차트·피벗·필터·정의된 이름·외부 연결·미지원 수식 등은 검사가 제한될 수 있습니다. 값 전용 사본의 수식은 입력을 바꿔도 다시 계산되지 않습니다.
- **CSV·TSV:** 수식 실행 방지를 위해 `=`, `+`, `-`, `@`로 시작하는 셀에 작은따옴표가 붙을 수 있습니다.

DOCX·PPTX는 원본과 분리한 화면 표시용 사본을 LibreOffice로 변환합니다. 쪽 번호·머리말·바닥글을 표시하고, 다른 자동 필드는 저장된 결과로 보여줍니다. 외부 연결을 갱신하지 않으며 내장 파일·실행 개체는 저장된 대체 그림이나 안내로 표시합니다. 표시 내용이 없거나 변환에서 제외한 부분은 화면 위 안내를 확인하세요. 이 과정은 원본이나 실제 수정 사본을 바꾸지 않으며, 연결 개체 내부의 수정까지 지원한다는 뜻은 아닙니다.

페이지 화면의 **이전 / 다음**과 **바로 이동**으로 쪽을 바꿀 수 있습니다. 내장 이미지도 같은 방식으로 넘겨 확인합니다. 반복 머리말·바닥글과 배치를 확인한 내장 이미지의 후보도 페이지에 표시하지만, 잘림·회전·동일 이미지 중복 등으로 배치를 확정하지 못한 이미지는 이미지 화면에서 검토하세요. 이미지의 저장 전 수정 모습은 이미지 화면에서, 페이지상의 실제 결과는 사본 생성 후 확인합니다.

암호화·미지원 내장 개체가 있는 문서는 검사나 저장이 제한될 수 있습니다. 화면의 **검사한 영역과 지원 범위** 안내를 함께 확인하세요.

</details>

기본 문맥 재검토는 이름·주소·생년월일 후보의 주변 문장·문단과 표 항목명을 모아 **같은 KoELECTRA 모델**로 다시 분석합니다. 날짜·기관명 판단과 문서 구조도 함께 사용하며, 불확실한 값은 개인정보 가능성을 고려해 남깁니다. 나머지 유형은 해당 유형의 규칙·문맥 보정을 사용합니다. 모든 유형에 모델 재검토를 적용하는 것은 아니며 추가 분석 시간이 필요합니다.

<details>
<summary>인증정보 탐지 범위와 처리 기준 — 0.1.2부터 제공</summary>

GitHub 토큰·OpenAI의 알려진 키 형식·Stripe 비밀·제한 키와, 명시적인 AWS Secret Access Key 항목 및 40자 값 형식을 확인합니다. 일반 API 키·client secret·access token 항목과 Authorization Bearer 값도 제한적으로 탐색합니다. AWS 접근 키 ID 단독이나 Stripe 공개용 키는 비밀 키로 취급하지 않습니다. 모든 서비스와 새로운 키 형식을 지원하는 것은 아닙니다.

비밀번호·패스워드·암호·password·passwd·pwd·passphrase 항목과 값을 연결하며 서비스명이 붙은 표 항목도 확인합니다. 짧거나 단순한 값에도 API 키의 길이·복잡도 기준을 적용하지 않습니다. 따옴표 안 공백·특수문자를 보존하고, 빈 값·명확한 안내·환경변수 참조·이미 가린 값은 구분합니다. 항목명 없는 임의 문자열은 비밀번호로 추측하지 않으며 모호한 문장이나 따옴표 없는 공백 포함 값은 놓치거나 잘못 검출할 수 있습니다.

실제 키 값의 대소문자·기호·원문 위치는 바꾸지 않으며 OCR로 끊기거나 잘못 읽힌 값을 추측해 복원하지 않습니다. 인증정보 후보는 개인정보용 모델의 판단으로 제외하지 않고 별도 규칙으로 검토합니다. 기본 위험도는 높음이며, 기존 고위험 정보와 겹치면 더 높은 위험도를 유지할 수 있습니다. 인증정보용 추가 모델이나 외부 유효성 확인 API는 사용하지 않습니다.

탐지는 노출 의심을 뜻하며 실제 키의 유효성·권한이나 로그인 성공 여부를 확인하지 않습니다. 합성 키도 알려진 형식과 같으면 후보가 될 수 있습니다. 이미 공유한 키는 문서 가림과 별도로 폐기·재발급을 검토하고 비밀번호는 해당 서비스에서 변경하세요. 검사 실패는 검출 0건으로 표시하지 않습니다.

</details>

<details>
<summary>선택 모델: Qwen3.5-0.8B 문맥 재검토 — 소스 환경의 시험 기능</summary>

**기본값은 KoELECTRA입니다.** [Qwen3.5-0.8B](https://huggingface.co/Qwen/Qwen3.5-0.8B)는 마지막 문맥 검토 단계의 KoELECTRA 재분석을 대신합니다. 두 문맥 검토 모델을 연속 실행하는 방식은 아닙니다. 원문 주변 문맥과 기존 후보를 분류하며 새 후보나 수정 문구를 생성하지 않습니다. 명확한 성명·생년월일 항목과 불확실한 후보는 유지합니다.

Qwen은 이름·주소·생년월일·나이·키·몸무게·직위·국적·학력·전공 후보를 검토합니다. 전화번호·계좌번호 등은 기존 규칙을 사용하고, 이미지는 기존 OCR로 읽은 글자만 검토합니다. Qwen의 이미지 입력 기능은 연결하지 않았습니다.

합성 문서 비교에서 오탐 감소와 함께 실제 개인정보를 잘못 제외하는 사례도 확인했습니다. 기본 방식보다 느리며 모델 실행 메모리가 추가로 필요합니다. 설치판에는 연결 코드·준비 도구만 제공하고 **Qwen 가중치와 추가 실행 도구를 자동 설치하지 않습니다.**

Windows x64 소스 환경을 준비한 뒤 실행합니다.

```powershell
.venv\Scripts\python.exe scripts\prepare\prepare_qwen_review.py
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start.ps1 -SecondaryModel qwen3.5-0.8b
```

처음 준비할 때 인터넷을 사용하며 Unsloth GGUF Q4_K_M 가중치 약 **533MB**와 llama.cpp CPU 도구를 해시로 검증합니다. 준비 명령에 `--enable`을 붙이면 이 소스 폴더의 기본값으로 저장합니다. 기본 모델로 실행하려면 `-SecondaryModel koelectra`를 사용하세요. 실행 중 설정 변경은 앱 재시작 후 반영됩니다. 자세한 고지는 [선택 모델 안내](models/QWEN-NOTICES.md)에 있습니다.

추가 모델은 GPU·외부 AI API 없이 PC에서 실행합니다. 임의 키로 보호하는 `127.0.0.1` 통신만 사용하며 문맥·응답을 파일 로그로 저장하지 않습니다. 모델·도구·선택 설정은 `.runtime/`에 보관합니다. 요청당 최대 5분이며 파일 검사 취소·앱 종료·시간 초과 때 추가 모델 프로세스를 정리하고, 모델 오류를 검출 0건으로 표시하지 않습니다.

</details>

## 확인된 오탐과 남은 제한

| 맥락 | 남아 있는 문제 |
|---|---|
| 이름·기관명·일반 표현 | 문장의 역할이나 표 항목을 잘못 연결해 일반 표현을 이름으로 남기거나 실제 이름을 놓칠 수 있습니다. |
| 학력·학교 약칭 | 일반 안내·지원 자격·동작 표현을 학교명이나 특정 개인의 학력으로 해석할 수 있습니다. |
| 날짜·나이 | 행사 일정·자격 조건과 개인의 생년월일·나이를 구분하는 데 오탐과 누락이 남아 있습니다. |
| URL 범위 | 바로 뒤의 한국어 조사나 설명 일부를 URL에 포함할 수 있습니다. |

| Qwen 선택 기능 | 일부 오탐을 줄이면서 실제 개인정보까지 제외한 사례가 있어 기본값으로 사용하지 않습니다. |

검출 결과와 위험도는 검토를 돕는 후보입니다. **검출 0건이나 OCR 재검사 0건이 개인정보가 없다는 보장은 아닙니다.** 부분 가림은 일부 정보를 남기므로 원본과 최종 사본을 함께 확인하세요. 예시의 검출 건수나 동작 검증 결과를 일반 문서의 탐지 정확도로 해석하지 마세요.

이 도구의 목적은 **공유 전 개인정보 노출 점검**입니다. 악성코드·바이러스 탐지는 제공하지 않습니다. 실행 개체·외부 참조·미지원 구조에 대한 처리 제한은 문서를 읽고 수정 사본을 검증하기 위한 보호 조치이며 악성 파일 판정이 아닙니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1
```

이후 루트의 `개인정보 자가진단 도구 실행.vbs`로 실행할 수 있습니다. 준비 스크립트는 Python 패키지·모델·OCR 데이터·hwplib를 준비하지만 JDK와 LibreOffice를 모두 설치해 주지는 않습니다.

Windows 소스 환경의 LibreOffice는 `.runtime/file-tools/libreoffice/program/soffice.com`과 필요한 구성요소를 준비해야 하며 일반 설치 경로에서 자동으로 찾지 않습니다. JDK는 `C:/Program Files/Java/jdk*/bin/java.exe` 또는 `PATH`에서 찾습니다. 도구가 없으면 연결된 HWP 읽기·수정 저장, Office 페이지·엑셀 재계산 기능을 사용할 수 없으므로 준비 결과의 `[MISSING]` 안내를 확인하세요.

`scripts/setup.sh`·`start.sh`는 Linux 브라우저 모드 보조 도구입니다. Windows 설치판과 동일한 지원 환경으로 검증한 것은 아닙니다. Linux OCR에는 Tesseract 개발 헤더·한국어·영어 데이터가, 문서 기능에는 Java·LibreOffice가 별도로 필요합니다.

설치판 빌드에는 개발 환경과 **JDK 11 이상·Inno Setup 6**가 필요합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build/build_installer.ps1
```

결과는 `installer/out/`의 설치 EXE·기본 예시 ZIP·게시글 ZIP·`SHA256SUMS.txt`입니다. 확장 테스트 ZIP은 별도 배포 자료입니다. 설치 파일은 Git 소스에 넣지 않고 GitHub Releases에 배포합니다.

공개 저장소에는 `src/`·`backend/`, 필수 설치·실행 스크립트와 의존성 설정, 사용 안내와 기본 예시 22개를 관리합니다. 추가 합성 예시 30개는 Release에서 제공하며 내부 개발 메모·보고서·자동 시험·상세 결과·개인 자료·실행 환경·빌드 결과·일반 `.piipost` 작업 파일은 Git 공개 대상에서 제외합니다.

프런트엔드 구성요소의 라이선스는 설치 폴더의 `THIRD-PARTY-NOTICES.txt`, 내려받는 라이브러리·모델·외부 도구는 각 배포물의 고지를 확인하세요.
