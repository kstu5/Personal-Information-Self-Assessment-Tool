# 개인정보 자가진단 도구

공유하기 전 게시글과 문서에서 개인정보 후보를 찾고, 사용자가 위치와 문맥을 확인해 가리거나 수정하는 **Windows용 로컬 프로그램**입니다. 현재 배포 버전은 **0.1.1**입니다.

**PNG·JPG·JPEG 이미지의 개인정보도 부분 가림·비공개 표시·직접 문구 수정이 가능합니다.** 원본과 적용 미리보기를 비교한 뒤 수정 사본을 PNG로 저장합니다.

**0.1.1은 문서 미리보기·페이지 이동·검사 진행 화면과 개인정보 문맥 보정을 개선한 버전입니다.** 기존 0.1.0 사용자는 작업을 저장하고 앱을 종료한 뒤 새 설치 파일로 업데이트하세요. 파일 드래그 앤 드롭과 이미지 문구 수정도 계속 지원합니다.

**현재도 오탐과 누락이 발생합니다.** 일반 단어·항목 기호가 이름으로, 동작 표현이 학교 약칭·학력으로 검출될 수 있습니다. 검출 결과는 확정 판정이 아닌 후보이며, 세부 내용은 아래 [확인된 오탐과 남은 제한](#확인된-오탐과-남은-제한)을 확인하세요.

## 설치와 실행

1. 실행 중인 이전 버전이 있다면 작업을 저장하고 종료합니다.
2. 위 설치 EXE를 실행하고 설치할 폴더를 선택합니다.
3. 인터넷에 연결한 상태로 설치가 끝날 때까지 기다립니다.
4. 시작 메뉴의 **개인정보 자가진단 도구**를 실행합니다.

설치 파일은 **Windows x64 온라인 설치판**입니다. Python·탐지 모델·OCR·Java·LibreOffice와 필요한 WebView2를 설치 중 준비하므로 인터넷 연결과 충분한 디스크 공간이 필요합니다. 사용자가 Python·Node.js·JDK를 따로 설치하거나 설치 프로그램을 직접 제작할 필요는 없습니다. 설치 이후 개인정보 검사는 PC 안에서 수행하며, 외부 생성형 AI API로 문서를 보내지 않습니다.

기본 설치 위치는 `%LOCALAPPDATA%\Programs\BeforePost`이고 설치 화면에서 바꿀 수 있습니다. 실행 구성요소의 긴 경로 오류를 피하도록 **설치 폴더의 전체 경로는 100자 이하**로 제한하며, 너무 길면 설치 전에 다른 위치를 선택하도록 안내합니다. 폴더 이름의 BeforePost는 기존 설치와의 호환성을 위한 내부 이름입니다. 실패하면 설치 폴더의 `install.log`에서 실패 단계를 확인하세요. 로그를 공유할 때는 개인 경로 등 불필요한 정보를 지우세요.

설치 EXE에는 코드 서명을 적용하지 않았습니다. Release의 `SHA256SUMS.txt`로 다운로드한 EXE·전체 예시 ZIP·게시글 예시 ZIP의 해시를 대조할 수 있습니다. GitHub의 **Source code ZIP/TAR는 개발용 소스**이며 설치 프로그램이 아닙니다. 설치 파일은 내려받은 버전의 Release 해시를 기준으로 확인하세요.

## 사용 방법

1. **게시글 검사** 또는 **파일 검사**를 선택합니다. 파일 검사는 **파일 추가** 버튼을 누르거나 탐색기의 파일을 검사 화면에 **드래그 앤 드롭**합니다. 여러 파일을 함께 놓을 수 있으며 폴더는 지원하지 않습니다.
2. 위험도별 검출 목록과 원문 위치를 함께 확인합니다.
3. 항목마다 지원하는 **부분 가림·전체 가림·직접 수정·가리지 않음**을 선택합니다. 미설정 항목은 원문 그대로 남습니다. HWP는 읽기 전용이며, PDF·문서 내장 이미지는 문구 교체 대신 영역 가림을 사용합니다.
4. **원본 / 적용 미리보기**를 전환해 변경 모습을 비교합니다.
5. 파일은 **사본 생성·재검사 → 실제 사본 확인**을 실행합니다. 남은 후보와 가림 범위를 검토하고 **남은 후보, 이미지 가림 범위, 지원 제한을 확인했습니다.**를 체크한 뒤 새 파일로 저장합니다. 원본에는 덮어쓰지 않습니다.

파일 검사 중에는 **대기 → 내용 읽기 → 개인정보 검사 → 검토 준비**를 단계형 카드로 표시합니다. 검사 구간 수가 확인되면 현재 구간도 보여주며, **작업 취소**로 중지할 수 있습니다. 검사가 끝나기 전에는 미완성 결과를 표시하지 않습니다. 사본 생성 중에는 같은 카드에서 수정 적용·재검사 단계를 확인할 수 있습니다.

게시글은 수정한 내용으로 이어 쓰거나 `.piipost` 작업 파일로 저장합니다. 이 파일은 제목·본문을 담은 암호화되지 않은 JSON이며, 파일 검사에서 선택한 처리 상태를 보관하는 형식은 아닙니다. 앱 종료·화면 새로고침 전에 필요한 사본을 저장하세요.

### 이미지의 가림과 직접 수정

독립된 **PNG·JPG·JPEG**는 선택한 개인정보의 원문 픽셀을 지우고 다음 내용을 다시 씁니다.

파일 검사에서 이미지를 추가하고 검출 항목을 누른 뒤 **직접 수정 → 바꿀 내용**에 입력하면 됩니다. **적용 미리보기**로 전환해 입력한 문구를 확인하세요. 미리보기는 저장 전 표시이며, 파일 저장에는 **사본 생성·재검사**가 필요합니다.

| 방법 | 예시 |
|---|---|
| 부분 가림 | `박**`, `010-****-2103` |
| 비공개 표시 | 이미지의 전체 가림 버튼으로, `비공개`라고 표시 |
| 직접 수정 | `담당자`, `테스트 test !@# ✓`처럼 입력한 문구. 빈 문구는 삭제 |

원문 글자 높이를 기준으로 새 글자의 크기를 추정하고 같은 줄의 빈 공간을 활용합니다. 좁은 폭에 맞춰 글씨를 작게 줄이지 않습니다. 일반 기호와 로컬 글꼴이 지원하는 체크·이모지를 표시합니다. 공간 부족·미지원 글자·수정 영역 겹침이 있으면 해당 영역의 원문과 경고를 표시하고 사본 생성을 중단합니다. 줄바꿈 등 잘못된 입력이나 미리보기 처리 실패 시에는 오류 안내와 함께 원본을 표시할 수 있으므로, 화면이 보인다는 것만으로 수정 완료로 판단하지 마세요. 직접 수정은 한 줄 80자 이하입니다.

적용 미리보기와 저장은 같은 이미지 처리를 사용합니다. **검출 표시 보기**로 위치 표시를 켜고 끌 수 있고, 자동 검출이 놓친 곳은 **직접 영역 가리기**로 검게 가립니다. 글꼴·사진·복잡한 배경은 원본과 다르게 보일 수 있습니다. 수정 사본은 메타데이터를 제거한 PNG로 저장하며 JPG·JPEG 입력도 PNG로 출력합니다.

PDF 페이지와 DOCX·PPTX·HWPX에서 읽어낸 지원 내장 이미지는 검은 영역 가림을 사용합니다. 이 화면에서는 직접 문구 수정이 비활성화되며, 부분 가림도 별표를 새로 쓰는 방식이 아니라 선택한 글자의 영역을 검게 지웁니다.

## 지원 파일과 제한

| 형식 | 확인 화면과 수정 범위 |
|---|---|
| TXT | 읽어낸 내용과 위치, 선택 가림·직접 수정. 사본은 UTF-8 |
| CSV·TSV | 행·열·빈 셀을 유지한 표, 셀 내용 가림·수정. 사본은 UTF-8 BOM |
| DOCX·PPTX | LibreOffice로 변환한 문서·슬라이드 페이지, 지원 텍스트와 부가 정보 수정. 메모·노트·속성도 별도 위치에서 확인 |
| HWPX | 추출 본문을 재구성한 내용, 지원 XML 텍스트·부가 정보 수정. 원래 쪽 배치 재현은 미지원 |
| HWP | 추출 본문 확인만 지원. **읽기 전용이며 수정 저장 미지원** |
| XLSX | 셀·숨김 영역·메모·속성 확인. 지원 수식 재계산 후 **값 전용 사본**으로 가림·수정. 그림·차트·피벗·외부 연결·필터 등은 미지원 |
| PDF | 실제 페이지와 글자층·OCR 위치 확인, 선택 영역의 글자·픽셀 삭제 후 가림. **새 문구 교체 미지원** |
| PNG·JPG·JPEG | 실제 이미지와 OCR 위치, 별표·비공개 표시·직접 문구 수정·직접 영역 가림. 출력은 PNG |

문서는 **원문 텍스트와 이미지에서 읽은 글자(OCR)를 구분**하며 검출 목록에도 읽은 방식을 표시합니다. DOCX·PPTX·HWPX의 본문은 직접 추출하고 지원되는 내장 PNG·JPEG·BMP만 OCR합니다. PDF는 정상 글자층을 직접 읽고 이미지·깨진 글자층·겹침이 있는 영역만 OCR로 보완합니다. 스캔 페이지는 전체를 OCR하며, 글자층과 이미지가 섞여 있어도 그림을 빠뜨리지 않도록 처리합니다. 화면 표시용 원본 이미지와 OCR 작업용 이미지는 분리합니다. HWP의 내장 이미지와 XLSX의 그림은 기존 지원 범위에 포함되지 않습니다.

파일당 **20MB**, 목록에 동시에 열 수 있는 파일은 **8개**입니다. 이미지는 **2천만 화소 이하**, 파일에서 읽어내는 이미지·PDF 페이지는 **40개 이하**, DOCX·PPTX의 변환 문서 화면은 **처음 40쪽**을 표시합니다. 그 뒤의 내용은 텍스트 · 위치에서 계속 확인할 수 있습니다. XLSX는 시트당 사용 범위가 **10만 셀 이하**여야 합니다. 텍스트·개체 수·처리 시간 제한도 있어 이 조건 안의 파일도 구조에 따라 거부될 수 있습니다.

PDF에 주석·링크·양식·서명·첨부·회전된 페이지 등이 있으면 검사만 가능하며 사본 생성을 제한합니다. 저장 가능한 PDF도 새 문서로 페이지를 복사하므로 목차·기본 문서 속성·접근성 태그 등은 보존하지 않습니다. XLSX의 그림·차트·필터·정의된 이름·외부 연결·미지원 수식 등은 검사를 거부할 수 있으므로 해당 기능을 제거한 값 전용 사본을 준비하세요. 암호화·미지원 내장 개체가 있는 다른 문서도 검사나 사본 저장을 제한할 수 있습니다.

Word·PowerPoint의 저장 전 문구 미리보기는 실제 사본의 줄바꿈·배치와 다를 수 있습니다. 실제 수정 사본을 확인하세요. HWP/HWPX 내용 화면은 원래 페이지·표·글꼴을 재현하지 않습니다. 엑셀 값 전용 사본은 입력을 바꿔도 수식을 다시 계산하지 않습니다.

DOCX·PPTX는 원본과 분리한 **화면 표시용 사본**으로 페이지를 만듭니다. 쪽 번호·머리말·바닥글이 있어도 화면을 표시하며, 다른 자동 필드는 저장된 결과로 보여줍니다. 외부 연결은 갱신하지 않고 내장 파일·실행 개체는 저장된 대체 그림이나 안내로 표시합니다. 저장된 표시 내용이 없거나 변환 과정에서 제외한 부분은 화면 위 안내를 확인하세요. 이 처리는 원본이나 실제 수정 사본의 내용을 바꾸지 않으며, 차트·연결 개체 내부 수정까지 지원한다는 뜻은 아닙니다.

DOCX·PPTX 문서 화면과 **PDF 페이지** 화면의 **이전 / 다음** 버튼으로 한 쪽씩 이동하거나 **바로 이동** 목록에서 원하는 쪽을 선택할 수 있습니다. 현재 쪽과 전체 표시 쪽 수를 함께 보여주며, 첫 쪽의 이전 버튼과 마지막 쪽의 다음 버튼은 비활성화됩니다. DOCX·PPTX는 쪽을 바꾸면 해당 페이지의 맨 위부터 표시합니다. 내장 이미지 화면에서도 같은 버튼으로 이전·다음 이미지를 확인할 수 있습니다.

반복 머리말·바닥글과 정확한 원본 이미지 배치를 확인한 내장 이미지의 후보도 페이지에서 표시합니다. 잘림·회전·동일 이미지 중복 등으로 배치를 확정하지 못한 이미지는 **이미지** 화면에서 검토하세요. 이미지의 저장 전 수정 모습은 이미지 화면에서 확인하고, 페이지에서는 사본 생성 후 실제 결과를 확인하세요. 메모·노트·속성은 본문 페이지 밖에도 있으므로 **텍스트 · 위치**를 함께 확인하세요. 페이지 변환이 실패해도 이 탭에서 검토를 계속할 수 있습니다. CSV·TSV 사본은 수식 실행 방지를 위해 `=`, `+`, `-`, `@`로 시작하는 셀에 작은따옴표를 덧붙일 수 있어 원문과 달라질 수 있습니다.

## 예시 문서 12종과 게시글 10개로 확인하기

[예시 목록과 사용 안내](examples/README.md)에서 파일을 하나씩 받거나 위 ZIP으로 한 번에 받을 수 있습니다. 설치 폴더의 `examples/formats/files/`와 시작 메뉴의 **개인정보 자가진단 도구 예시 문서**에도 같은 12종을 제공합니다.

게시글 예시는 `examples/posts/`와 시작 메뉴의 **개인정보 자가진단 도구 게시글 예시**에서 찾을 수 있습니다. **게시글 검사 → 저장한 글 불러오기**에서 `.piipost` 하나를 선택하면 제목과 본문을 그대로 불러옵니다. 이 파일은 **파일 검사**에 추가하는 문서가 아닙니다. 모임 안내·당첨자 발표·배송 요청·채용 공고 등 10가지 상황을 구성했습니다. 수정한 글은 다른 이름으로 저장해 이어서 사용할 수 있습니다.

TXT·CSV·TSV·DOCX·PPTX·HWPX·HWP·XLSX·PDF·PNG·JPG·JPEG를 실제 공유 상황의 문서로 구성했습니다. 모든 인적사항·기관명은 합성 정보입니다. 한 번에 8개까지 열 수 있으므로 12종은 두 묶음으로 검사하세요. 후보 수뿐 아니라 실제 위치, 메모·숨김 영역, 수정 사본에 남은 정보와 보존할 내용을 함께 비교하세요.

## 사용하는 탐지 방식

이름·주소에는 **[atonlee/koelectra-ko-pii-ner](https://huggingface.co/atonlee/koelectra-ko-pii-ner)**를, 전화번호·이메일 등 다른 유형에는 **ko-pii 1.16.0 규칙**을 결합합니다. 모델 파일은 고정 리비전과 해시로 확인합니다. 흐림·기울기·필기·모호한 문맥에는 누락과 오탐이 있을 수 있습니다.

기본 설정에서는 이름·주소·생년월일 후보를 찾은 뒤, 프로그램이 주변 문단과 표의 머리글·같은 행을 모아 **자동 2차 검토**를 수행합니다. 같은 KoELECTRA 모델로 해당 문맥을 다시 분석하고, 일반 날짜·생년월일·기관명 판단과 문서 구조를 함께 사용해 후보 유지·오탐 제외를 결정합니다. 모델이 일반 날짜로 판단했다는 이유만으로 생년월일을 제외하지 않으며, 모호한 값은 개인정보 가능성을 고려해 후보로 유지합니다. 번호의 형식 검증은 기존 규칙을 유지합니다. 기본 방식은 별도 모델 추가·재학습 없이 내 PC에서 처리하며, 중복 문맥을 묶어 처리하지만 추가 분석 시간이 필요합니다. 재검토 뒤에도 오탐과 누락이 남을 수 있습니다.

항목 기호와 모집군은 일반 문맥 보정에서도 구분합니다. 목록·입학 문맥의 표현을 이름으로 판단하는 일부 오탐을 줄이고, 명시적 성명 항목이나 호칭처럼 사람을 나타내는 근거가 있는 값은 유지합니다. 같은 글자를 문서 전체에서 일괄 제외하지 않습니다.

### 선택 기능: Qwen3.5-0.8B로 2차 문맥 검토

소스 실행 환경에서 **[Qwen3.5-0.8B](https://huggingface.co/Qwen/Qwen3.5-0.8B)**를 2차 판별기로 선택할 수 있습니다. 1차 KoELECTRA·번호 규칙은 유지하고, 2차 재분석만 Qwen으로 바꿉니다. 두 2차 모델을 연속 실행하는 방식은 아닙니다. Qwen은 기존 후보와 원문 주변 문맥을 받아 개인정보·일반 표현·불확실로 분류하며 새 후보나 수정 문구를 생성하지 않습니다. 명확한 성명·생년월일 항목은 모델이 거부해도 유지하고, 불확실한 후보도 남깁니다.

Qwen은 이름·주소·생년월일·나이·키·몸무게·직위·국적·학력·전공 후보를 검토합니다. 전화번호·계좌번호 등 번호 판정은 기존 규칙을 사용합니다. 이미지는 기존 OCR로 읽은 글자를 검토하며, Qwen의 이미지 입력 기능을 연결한 것은 아닙니다.

**시험용 선택 기능입니다.** 합성 문서 비교에서 오탐 감소와 함께 실제 개인정보를 잘못 제외하는 사례도 확인했습니다. 기본값은 KoELECTRA입니다. 0.1.1 설치판에는 선택 기능의 연결 코드·준비 도구를 제공하며, Qwen 가중치·추가 실행 도구는 포함하거나 자동 설치하지 않습니다.

Windows x64 소스 환경을 준비한 후 다음 명령으로 선택 모델을 내려받고 실행합니다.

```powershell
.venv\Scripts\python.exe scripts\prepare\prepare_qwen_review.py
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start.ps1 -SecondaryModel qwen3.5-0.8b
```

처음 준비할 때만 인터넷을 사용합니다. 고정 리비전의 Unsloth GGUF **Q4_K_M 가중치 약 533MB**와 llama.cpp Windows CPU 실행 도구를 해시로 검증합니다. 준비 스크립트에 `--enable`을 붙이면 이 소스 폴더의 기본값으로 저장하며, 되돌릴 때는 `.runtime/secondary-review.json`을 지우고 앱을 다시 실행하거나 `-SecondaryModel koelectra`로 실행하세요. 실행 중 모델 설정을 바꾸려면 앱을 재시작해야 합니다. 소스·라이선스 안내는 [선택 모델 고지](models/QWEN-NOTICES.md)에 있습니다.

검사는 GPU·외부 AI API 없이 PC 안에서 수행합니다. 로컬 통신은 임의 키를 사용하는 `127.0.0.1` 서버로 제한하고 문맥·응답을 파일 로그로 저장하지 않습니다. 모델·실행 도구·선택 설정은 `.runtime/`에 보관하며 Git 공개 대상에서 제외합니다. 가중치 파일 크기 외에 모델 실행 메모리가 추가로 필요하고, 후보마다 문맥을 검토하므로 기본 방식보다 느립니다. 2차 검토는 한 요청당 최대 5분이며, 파일 검사의 작업 취소·앱 종료·시간 초과 시 추가 모델 프로세스를 함께 정리합니다. 시간 초과나 모델 오류를 검출 0건으로 표시하지 않습니다.

### 확인된 오탐과 남은 제한

**0.1.1에서도 개인정보가 아닌 내용을 검출하는 오탐과 실제 개인정보를 놓치는 누락이 남아 있습니다.** 문맥 보정과 2차 검토를 적용했다고 정확한 판정이 보장되는 것은 아닙니다.

| 유형 | 남아 있는 문제 |
|---|---|
| 이름·기관명·일반 단어 | 일반 표현이나 한 글자 항목이 이름 후보로 남을 수 있습니다. 이름 항목의 짧은 한글 값을 복원하는 과정에서도 일반 단어가 추가될 수 있습니다. |
| 학력·학교 약칭 | 문장 속 동작 표현이나 일반적인 지원 자격을 학교명·특정 개인의 학력으로 해석할 수 있습니다. 이 문맥의 오탐은 이번 버전에도 남아 있습니다. |
| 날짜·나이 | 일반 일정·자격 조건과 특정 개인의 생년월일·나이를 구분하는 데 오탐과 누락이 발생할 수 있습니다. |
| OCR·문서 구조 | 이미지 품질·기울기·복잡한 표·분리된 문장 때문에 글자를 잘못 읽거나 문맥을 연결하지 못할 수 있습니다. |
| Qwen 선택 기능 | 일부 오탐을 줄이지만 실제 개인정보까지 제외한 사례가 있어 기본값으로 사용하지 않습니다. |

기본 방식의 모델 2차 검토는 이름·주소·생년월일을 대상으로 합니다. 다른 유형은 해당 유형의 규칙·문맥 보정을 사용하므로, 모든 검출 유형에 모델 재검토가 적용되는 것은 아닙니다. Qwen 선택 모드의 대상 범위는 위 안내를 참고하세요.

검출 결과와 위험도는 검토를 돕는 후보입니다. **검출 0건은 개인정보가 없다는 보장이 아니며**, 부분 가림은 일부 정보를 남기는 선택입니다. 공유 전 원문과 수정 사본을 함께 확인하세요. 현재 결과나 예시 문서의 검출 건수를 전체 문서에 대한 정확도로 해석해서는 안 됩니다.

이 제품의 목적은 **다른 사람에게 공유하기 전 개인정보 노출을 점검하는 것**입니다. 악성코드·바이러스 탐지 기능은 제공하지 않습니다. 실행 개체·외부 참조·미지원 문서 구조에 대한 처리 제한은 문서를 읽고 수정 사본을 검증하기 위한 보호 조치이며, 파일이 악성이라고 판정한 결과는 아닙니다.

## 개발자용 소스 실행·설치판 제작

일반 사용자는 위 완성 설치 EXE를 사용합니다. 소스 실행에는 Python 3.12 이상, Node.js/npm, Windows WebView2가 필요합니다. 설치판의 Python은 3.12 x64입니다. 소스에서 HWP를 읽으려면 Java 소스 실행이 가능한 **JDK 11 이상**, Office 페이지·엑셀 재계산에는 LibreOffice가 필요합니다. 소스 준비 스크립트는 OCR 데이터·hwplib·모델을 준비하지만 JDK와 LibreOffice를 모두 설치해 주지는 않습니다.

```powershell
git clone https://github.com/kstu5/Personal-Information-Self-Assessment-Tool.git
cd Personal-Information-Self-Assessment-Tool
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1
```

이후 루트의 **개인정보 자가진단 도구 실행.vbs**로 실행할 수 있습니다. `scripts/setup.sh`·`start.sh`는 Linux 브라우저 모드 보조 도구이며 Windows 설치판과 동일한 지원 환경으로 검증한 것은 아닙니다. Linux OCR에는 Tesseract 개발 헤더와 한국어·영어 데이터, 문서 기능에는 Java·LibreOffice가 별도로 필요합니다.

Windows 소스 환경에서 LibreOffice는 `.runtime/file-tools/libreoffice/program/soffice.com` 위치에 실행 파일과 필요한 구성요소가 있어야 합니다. 일반 설치 경로에서 자동으로 찾지는 않습니다. JDK는 `C:/Program Files/Java/jdk*/bin/java.exe` 또는 `PATH`에서 찾습니다. 준비 결과의 `[MISSING]` 항목을 확인하세요. 해당 도구가 없으면 HWP 읽기·Office 페이지 미리보기·엑셀 수식 재계산 등 연결된 기능을 사용할 수 없습니다.

Windows 설치판 제작에는 위 개발 환경과 JDK 11 이상, Inno Setup 6가 필요합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build/build_installer.ps1
```

결과는 `installer/out/`의 설치 EXE·예시 ZIP·`SHA256SUMS.txt`입니다. 설치 파일은 Git 소스에 넣지 않고 GitHub Releases에 배포합니다. 설치판에 포함하는 프런트엔드 구성요소의 라이선스는 설치 폴더의 `THIRD-PARTY-NOTICES.txt`, 내려받는 라이브러리·모델·외부 도구의 라이선스는 각 배포물의 고지를 확인하세요.

공개 저장소에는 `src/`, `backend/`, 필수 설치·실행 스크립트와 의존성 설정, 사용 안내, 문서 예시 12종과 게시글 예시 10개를 관리합니다. 개발 메모·보고서·추가 시험 문서·자동 시험 코드·상세 결과·개인 자료는 공개 목록에서 제외합니다. 실행 환경·빌드 결과도 Git에서 제외하며, 예시 폴더 밖의 일반 `.piipost` 작업 파일도 제외합니다.
